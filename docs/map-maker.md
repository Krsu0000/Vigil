# T1 제작자 맵 생성기

배포/PR 미리보기 주소 뒤에 `/map-maker.html`을 붙이면 제작자 화면이 열린다. 로컬에서는 `npm run dev` 후 같은 경로를 연다. 생성기는 별도 진입점이며 기본 게임 화면과 자동 저장을 연결하지 않는다.

## 화면에서 사용하기

1. 기존 게임을 확장하려면 **현재 게임 맵 불러오기**를 먼저 누른다. 기본으로 보이는 생성 맵은 새 제작 초안이다.
2. 시드·크기·방·통로 설정으로 **새 맵으로 추가**하거나 **층 추가**를 누른다. **맵 생성**은 선택한 맵 전체를 교체하고 그 맵의 기존 출입구도 해제한다.
3. 지도를 눌러 칸을 선택하거나 선택 X/Y를 입력한다. 확대 배율을 조절하며 바닥/벽·안전/위험 구역·상자·적을 편집한다. **되돌리기**는 최근 20번 편집까지 지원한다.
4. 출입구 칸에서 문/계단/포탈 종류와 도착 맵·층·X/Y를 지정하고 **왕복 출입구 연결**을 누른다. **도착 맵의 시작점과 연결**은 좌표 입력을 생략하는 방법이다. 양쪽은 상자·적이 없는 바닥이어야 하며 돌아오는 출입구도 함께 만든다. 기존 상대가 있으면 이전 연결을 해제한다.
5. **전체 검증**으로 고립된 지형·중복 배치·끊어진 출입구를 확인한다. 새 맵/층은 시작 맵에서 연결되어야 시험·내보내기가 가능하다. 편집 도중에는 미완성 상태를 허용한다.
6. **걸어 보기**는 지형·비용·안개만, **게임에서 시험**은 실제 게임 UI·시간·아이템·전투를 사용한다. 출입구에 선 뒤 Z/스페이스 또는 이동 버튼을 눌러 이동한다. 밟는 즉시 이동하지 않는다. **제작 화면으로** 돌아오면 편집 원본을 유지한다.
7. **배포용 맵 묶음 내보내기**로 저장하고 아래 등록 명령을 실행한다. JSON 파일을 전달해 등록을 요청해도 된다. 단일 맵의 **JSON 내려받기**는 기존 배열 형식을 유지하고 여러 맵/층은 묶음으로 내보낸다. **수정한 JSON 불러오기**는 두 형식을 지원하며 오류가 나면 현재 작업을 교체하지 않는다.

제작 초안과 시험 진행은 새로고침 후 자동 복원되지 않으므로 편집 후 JSON을 내려받는다. 두 시험 모두 새 임시 Store를 쓰고 기존 IndexedDB 슬롯을 읽거나 쓰지 않는다. 지형 시험에서만 상자/적을 제외하며, 게임 시험에서는 실제 배치를 유지한다. 게임 시험은 제작 화면으로 돌아올 때 시간 루프도 종료한다. 지형 시험에서 스태미나를 다 쓰면 다시 시작할 수 있다.

상자·조우 ID는 일회성 획득/토벌 기록의 식별자이므로 전체 맵에 각각 한 번만 배치할 수 있다. 현재 목록은 기존 콘텐츠 정의를 사용하며 새 물품/몬스터 정의 편집이나 자동 배치는 포함하지 않는다. 지형 복제는 상자·적·출입구를 제외한다.

## 맵 묶음을 배포 게임에 등록하기

```sh
npm run register:world -- --file vigil-world.json
npm run register:world -- --file vigil-world.json --apply
npm run validate:content
npm run build
```

첫 명령은 검사만 하고 파일을 쓰지 않는다. `--apply`는 변경 전 파일 원문을 `artifacts/world-backups/world-*/before.json`에 보관한 뒤 기존 맵 파일과 `maps/registered-world.json`, 매니페스트를 갱신한다. 적용 중 오류는 이전 파일로 되돌린다. 같은 묶음을 다시 적용하면 추가 변경을 만들지 않는다. 이후 Git 작업 브랜치에 커밋·PR을 만들고 병합/배포하면 기본 게임에 반영된다. 브라우저에서 내보내는 것만으로 배포 게임이 바뀌지는 않는다.

기존 저장 호환을 위해 현재 시작 맵과 모든 기존 맵의 ID·버전·시작점·층 크기·지형·안전/위험 구역·기존 상자/적 배치를 보존해야 한다. 새 맵/층·왕복 출입구 추가는 가능하다. 기존 지형을 크게 바꾸려면 **선택 맵 지형 복제**로 새 ID의 맵을 만들고 원래 맵은 남긴다. 기존 맵 삭제·이름뿐 아닌 ID 변경·버전 상승·거점 변경은 등록 검사에서 거부한다. 제작자 화면에서는 자유롭게 편집할 수 있지만 호환 조건에 맞지 않으면 배포 등록을 할 수 없다.

이번 등록 경로는 기존 전투 수치/정의와 저장 해석을 보존하는 추가 변경용이다. 콘텐츠 버전0.4.0/SaveFile7/DB1을 유지해 진행 중인 기존 전투도 복원한다. 임의의 전투 수치 변경에 같은 버전을 사용해도 된다는 뜻은 아니다. 실제 배포할 맵 디자인은 별도로 선택한다.

## Node CLI

```sh
npm run generate:map -- --seed 1,2,3,4 --width 64 --height 48 --rooms 12 --out artifacts/generated-map.json
npm run validate:content -- --map artifacts/generated-map.json
```

`generate:map`은 생성 결과를 기존 콘텐츠 로더로 검증한 뒤 맵 정의 1개를 담은 JSON 배열로 쓴다. 출력 경로의 기존 파일은 덮어쓰지 않는다. 다른 파일 이름으로 다시 생성하거나 필요한 파일을 보관한 뒤 삭제한다. `--help`로 옵션을 확인한다.

`validate:content -- --map`은 해당 맵 파일을 현재 저장소의 타일·구역·아이템·상자·몬스터·조우 정의와 함께 메모리에서 검사한다. 기본 맵 파일과 매니페스트는 바꾸지 않는다. 기존의 `validate:content [콘텐츠 폴더]` 명령도 유지한다.

| 설정 | CLI 옵션 | 기본값 / 범위 |
|---|---|---|
| 시드 | `--seed` | `1,2,3,4` / 0~4294967295 정수 4개 |
| 가로·세로 | `--width`, `--height` | 64×48 / 각 9~512칸 |
| 방 개수 | `--rooms` | 12 / 1~128개, 실제 배치할 수 있어야 함 |
| 방 크기 | `--room-min`, `--room-max` | 3~9 / 최소 3~31, 최대 3~63, 두 변 각각 적용 |
| 통로 직진 성향 | `--straightness` | 0.6 / 0~1 |
| 막다른 가지 유지 비율 | `--dead-end-retention` | 0.35 / 0~1, 초기 막다른 가지를 유지할 확률 |
| 추가 연결 수 | `--extra-connections` | 6 / 0~256, 가능한 후보 수까지 추가 |
| 맵 ID | `--id` | `map.generated` / 기존 map ID 규칙 |
| 맵 버전 | `--version` | 1 / 양의 안전한 정수 |
| 출력 경로 | `--out` | `artifacts/generated-map.json` |

같은 **생성기 v1·시드·모든 설정**이면 같은 JSON을 만든다. 시드만 같고 설정이 다르면 결과도 달라질 수 있다. 시간이나 플레이 중 난수를 사용하지 않는다. 기본 설정은 제작을 시작하기 위한 임시값이다.

## 생성·검증 방식

- 공간을 분할해 방 자리를 확보한 뒤 각 자리에 방을 만든다. 요청한 방 개수를 배치할 수 없으면 개수를 줄여 출력하지 않고 거부한다.
- 홀수 격자의 깊이 우선 미로를 명시적 스택으로 연결하고 방을 합친다. 통로 직진 성향은 가능한 다음 방향에서 기존 방향을 우선할 확률이다.
- 방을 보호하며 막다른 가지를 확률적으로 남기거나 걷어 낸다. 유지 비율은 최종 바닥 중 막다른 길의 점유율이 아니다. 방·통로의 연결 상태에 따라 실제 끝 개수가 달라지므로 결과에 실제 개수도 표시한다.
- 연결된 바닥 사이의 벽을 열어 추가 경로를 만든다. 외곽은 1칸 벽으로 유지하고 첫 방을 안전 구역, 나머지를 위험 구역으로 둔다. 시작점은 첫 방 안에 둔다.
- 기존 스키마·참조·배치 검사에 더해 네 방향 연결을 검사한다. 시작 층은 시작점, 그 외 층은 첫 이동 가능 칸을 기준으로 층 안의 고립된 바닥을 검사한다. 재귀나 큐의 `shift()`를 사용하지 않으며 O(N) 시간·공간을 사용한다. 잘못된 치수/배치/참조는 밀집 배열을 만들기 전에 거부한다.

## 범위

여러 맵/층 편집, 왕복 문·계단·포탈, 시작 맵 지정, 실제 게임 시험과 저장 호환 등록을 지원한다. 각 층 내부는 네 방향으로 연결되어야 하며 층 사이 이동은 출입구로 연결한다. 문·계단·포탈은 현재 같은 이동 구조이고 별도 열쇠/비용/연출은 없다. 출입구 자체는 스태미나·시간·난수를 소비하지 않으며 게임 UI에서는 이동과 같은 100ms 입력 간격을 사용한다. 도착 직후 반대편으로 자동 이동하지 않는다.

위험 구역의 귀환은 지정된 시작 맵의 거점으로 이동한다. 안전 구역·조우/전투·사망 중 귀환 제한은 기존 규칙을 유지한다. 새 맵으로 이동해도 이전 탐사·아이템·토벌·최근 기록은 보존한다. 원정/캐릭터 생성 시 맵을 다시 굴리거나 적·상자를 초기화하는 규칙은 추가하지 않는다.

고정 이벤트·자동 몬스터/전리품 배치·채집지·새 물품/조우 정의 편집은 후속이다. 검증 명령과 결과는 `verification.md`, `progress.md`를 참조한다.
