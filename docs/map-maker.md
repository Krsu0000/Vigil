# T1 제작자 맵 생성기

배포/PR 미리보기 주소 뒤에 `/map-maker.html`을 붙이면 제작자 화면이 열린다. 로컬에서는 `npm run dev` 후 같은 경로를 연다. 생성기는 별도 진입점이며 기본 게임 화면과 자동 저장을 연결하지 않는다.

## 화면에서 사용하기

1. 시드와 가로·세로 칸 수, 방 개수·크기, 통로 설정을 입력하고 **맵 생성**을 누른다.
2. 전체 지형에서 방과 통로, 안전 구역과 시작 위치를 확인한다. 표시된 방 개수와 실제 막다른 끝/추가 연결 수를 확인한다.
3. **걸어 보기**에서 기존 이동 엔진·이동 비용·안개·벽 표시를 사용해 이동한다. 방향키/WASD 또는 방향 버튼으로 조작한다. 시작 위치로 돌아올 수 있다.
4. **제작 화면으로** 돌아와 JSON을 내려받는다. JSON을 직접 수정한 뒤 **수정한 JSON 불러오기**로 검사할 수 있다. 잘못된 수정본은 오류를 표시하고 직전의 유효한 맵을 유지한다.

이동 시험은 매번 새 임시 상태로 시작한다. 시간 루프·자동 저장을 연결하지 않으며 기존 IndexedDB 슬롯을 읽거나 쓰지 않는다. 불러온 맵의 상자·적 배치는 내려받는 원본에 보존하고, 지형 이동 시험의 복사본에서만 제외한다. 긴 탐험 중 스태미나를 다 쓰면 제작 화면으로 돌아와 시험을 다시 시작할 수 있다.

## Node CLI

```sh
npm run generate:map -- --seed 1,2,3,4 --width 64 --height 48 --rooms 12 --out artifacts/generated-map.json
npm run validate:content -- --map artifacts/generated-map.json
```

`generate:map`은 생성 결과를 기존 콘텐츠 로더로 검증한 뒤 맵 정의 1개를 담은 JSON 배열로 쓴다. 출력 경로의 기존 파일은 덮어쓰지 않는다. 다른 파일 이름으로 다시 생성하거나 필요한 파일을 보관한 뒤 삭제한다. `--help`로 옵션을 확인한다.

`validate:content -- --map`은 해당 맵 파일을 현재 저장소의 타일·구역·아이템·상자·몬스터·조우 정의와 함께 메모리에서 검사한다. 기본 맵 파일과 매니페스트는 바꾸지 않는다. 기존의 `validate:content [콘텐츠 폴더]` 명령도 유지한다.

| 설정 | CLI 옵션 | 기본값 / 범위 |
|---|---|---|
| 시드 | `--seed` | `1,2,3,4` / 0~4294967295 정수 4개 |
| 가로·세로 | `--width`, `--height` | 64×48 / 각 9~512칸 |
| 방 개수 | `--rooms` | 12 / 1~128개, 실제 배치할 수 있어야 함 |
| 방 크기 | `--room-min`, `--room-max` | 3~9 / 최소 3~31, 최대 3~63, 두 변 각각 적용 |
| 통로 직진 성향 | `--straightness` | 0.6 / 0~1 |
| 막다른 가지 유지 비율 | `--dead-end-retention` | 0.35 / 0~1, 초기 막다른 가지를 유지할 확률 |
| 추가 연결 수 | `--extra-connections` | 6 / 0~256, 가능한 후보 수까지 추가 |
| 맵 ID | `--id` | `map.generated` / 기존 map ID 규칙 |
| 맵 버전 | `--version` | 1 / 양의 안전한 정수 |
| 출력 경로 | `--out` | `artifacts/generated-map.json` |

같은 **생성기 v1·시드·모든 설정**이면 같은 JSON을 만든다. 시드만 같고 설정이 다르면 결과도 달라질 수 있다. 시간이나 플레이 중 난수를 사용하지 않는다. 기본 설정은 제작을 시작하기 위한 임시값이다.

## 생성·검증 방식

- 공간을 분할해 방 자리를 확보한 뒤 각 자리에 방을 만든다. 요청한 방 개수를 배치할 수 없으면 개수를 줄여 출력하지 않고 거부한다.
- 홀수 격자의 깊이 우선 미로를 명시적 스택으로 연결하고 방을 합친다. 통로 직진 성향은 가능한 다음 방향에서 기존 방향을 우선할 확률이다.
- 방을 보호하며 막다른 가지를 확률적으로 남기거나 걷어 낸다. 유지 비율은 최종 바닥 중 막다른 길의 점유율이 아니다. 방·통로의 연결 상태에 따라 실제 끝 개수가 달라지므로 결과에 실제 개수도 표시한다.
- 연결된 바닥 사이의 벽을 열어 추가 경로를 만든다. 외곽은 1칸 벽으로 유지하고 첫 방을 안전 구역, 나머지를 위험 구역으로 둔다. 시작점은 첫 방 안에 둔다.
- 기존 스키마·참조·배치 검사에 더해 네 방향 연결을 검사한다. 시작 층은 시작점, 그 외 층은 첫 이동 가능 칸을 기준으로 층 안의 고립된 바닥을 검사한다. 재귀나 큐의 `shift()`를 사용하지 않으며 O(N) 시간·공간을 사용한다. 잘못된 치수/배치/참조는 밀집 배열을 만들기 전에 거부한다.

## 범위

현재 생성과 제작자 미리보기는 단일 층 지형을 지원한다. 문·계단·고정 이벤트·자동 몬스터/전리품 배치·채집지 생성·화면에서 칸을 그리는 편집기는 후속이다. 수동 수정은 JSON으로 한다. 전체 콘텐츠 검증의 층 내부 연결 검사는 층 사이 이동 경로를 검증하는 기능이 아니다.

생성한 맵을 배포 게임의 기본 맵으로 자동 채택하지 않는다. 채택할 때는 맵 ID/버전과 기존 세이브 호환 정책을 정한 뒤 콘텐츠 변경으로 반영한다. 원정/캐릭터 생성 시 맵을 다시 굴리거나 적·상자를 초기화하는 규칙도 이번 작업에 포함하지 않는다.

검증 명령과 결과는 `verification.md`, `progress.md`를 참조한다.
