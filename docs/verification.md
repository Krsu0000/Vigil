# 반복 실행 가능한 검증

## 명령

```sh
npm ci
npm run typecheck
npm test
npm run validate:content
npm run build
npm run test:browser
npm run bench:map
```

개발 중에는 관련 테스트와 필요한 브라우저 시나리오만 실행하고 최종 전체 검사는 한 번 실행한다. 통과 후 코드 변경이나 새 우려가 없으면 반복하지 않는다.

## 브라우저 검사 준비

제품에는 브라우저 검사 도구를 포함하지 않는다. 별도 검사 환경에서 Playwright 1.62.1과 Chromium을 준비한다. 프로젝트 설치 후 아래 명령으로 로컬 검사 도구만 추가할 수 있다. package.json/잠금 파일은 변경하지 않는다.

```sh
npm install --no-save --package-lock=false playwright@1.62.1
npx playwright install chromium
npm run build
npm run test:browser
```

Codex의 준비된 실행 환경에서는 `CODEX_PRIMARY_RUNTIME_NODE_MODULES`의 Playwright도 사용할 수 있다. 별도 Chromium 바이너리를 쓸 때는 `BROWSER_CHROMIUM_EXECUTABLE`을 지정한다. 제품은 IBM Plex Sans KR/Mono를 로컬로 제공하므로 별도 폰트 주입은 필요 없다. 기존 BROWSER_FONT_DIR 검사 옵션은 남아 있지만 S5 화면 확인에서는 사용하지 않는다.

결과 JSON과 스크린샷은 Git에서 제외한 `artifacts/browser/`에 생성한다. `BROWSER_ARTIFACTS`로 출력 위치를 바꿀 수 있다. `BROWSER_SUITE=map`은 큰 맵 검사만 실행한다.

## 검사 범위

- **제품 배포 빌드, 1440/390/320px:** 99/100ms 입력 경계, 게임 자동 반복 없음, 화면 버튼·Space/Enter, 정지 차단, 연속 조작 중 실제 IndexedDB 저장, 파일 내보내기/가져오기 왕복, 가로 넘침·콘솔 오류.
- **개발 전용 합성 맵, 128×128/512×512:** 표시 DOM 칸 수 상한, 실제 좌표/접근성 인덱스, 먼 좌표 스크롤, 미탐사 정보 숨김, 시야 밖 벽 재가림, 이동 시 플레이어 추적, 화면 크기 변경.
- 합성 맵 진입점은 `tests/browser/fixture.html`이다. 제품의 index.html 및 빌드 진입점에서 참조하지 않는다. 검사에 쓰는 store/loop 노출은 이 진입점에만 있다.
- 브라우저 검사와 모바일 크기 검사는 사용자의 실제 기기 확인을 대체하지 않는다. 제품 시나리오는 가짜 시계를 사용하고, 큰 맵 시나리오는 실제 ResizeObserver/스크롤/레이아웃을 사용한다.

## 큰 맵 측정

`npm run bench:map`은 32/128/512 한 변 크기의 합성 맵을 실제 콘텐츠 로더로 고정한 뒤, 최초 로딩/좌표 인덱스 생성/10만 번 조회/전체 탐사 기록 검증/화면 표시 범위 계산 시간을 각각 출력한다. 시간값은 환경 의존 관측치이며 통과 기준으로 쓰지 않는다.

좌표 인덱스 생성과 콘텐츠 로딩은 전체 칸 수에 비례한다. 인덱스 이후 한 칸 조회는 상수 시간이고, 화면 계산·DOM 수는 표시 범위에 비례한다. 전체 저장 직렬화·복원 검증 및 새 탐사 기록의 불변 복사 비용은 여전히 기록 크기에 비례한다. 더 큰 실제 콘텐츠가 준비되면 최초 로딩과 저장 지연을 실제 폰에서도 측정한다. 이번 검증으로 임의 크기 지도의 성능을 보장하지 않는다.


## S4 아이템 회귀

`test:browser`는 `scripts/browser-inventory.mjs`도 실행한다. 제품 배포 빌드의 입력으로 보급 상자 획득, 소지품 내 키 입력, 최대치 음식 차단, 장착/해제 비용 표시와 실제 이동 차감, 창을 열어 둔 시간/회복, 음식 한 개 소모/총중량, IndexedDB 저장 후 새로고침/중복 상자 차단을 1280/390/320px에서 검사한다. 제품 전역에 검사 API를 추가하지 않는다.

S4 엔진/콘텐츠/저장 회귀는 `src/engine/systems/inventory/actions.test.ts`, `src/content/items.test.ts`, `src/runtime/inventory.test.ts`에 있다. 제품 JSON을 사용하는 회귀와 기존 맵만의 독립 검사를 구분한다. 실제 폰 플레이에서는 (3,1) 보급 상자 → 소지품 장화 장착 → (4,3) 위험 구역 → 음식 → 귀환 → 새로고침을 확인한다.


D-039 후속 검사는 상자 열기 직후 성공 안내/품목/수량, 재방문 시 빈 상자 안내, 기존 결과를 덮지 않는 재입력, 정지 중 단축키 차단을 포함한다. 배포 빌드의 1280px은 버튼, 390px은 Z, 320px은 Space로 획득한다. 포커스된 이동 버튼의 기본 Space/Enter와 모달 내 입력 회귀도 함께 확인한다.


## S5 전투/UI 회귀

`browser-combat.mjs`는 실제 배포 빌드에서 늑대 무리 접촉 → 전투 시작 → 공격/방어/아이템/강타 → 승리/전리품 → 다른 적에게서 도주/직전 칸/적 유지까지 검사한다. 전투 도중 현실 시계를 진행해 회복/게임 시간이 멈춘 것을 확인하고 실제 IndexedDB 저장 후 새로고침으로 이어서 싸운다. 제품에 검사 Store/API를 노출하지 않는다. 재현을 위해 브라우저 검사 세션의 초기 crypto 시드만 [1,2,3,4]로 고정한다.

PC1440×900, 모바일390×844/320×900에서 전투480px/하단시트·캐릭터600px·탭/전체지도·390px 지도 칸28px/가용 높이(D-044)·로컬 Plex 폰트와 상단 정지 버튼 제거도 확인한다. 큰 맵 검사에서는 실제 지도 리사이즈/스크롤/플레이어 추적/틱 메모화를 유지한다. 결과 JSON/캡처는 artifacts/browser에 생성한다.

Vitest의 신규 runtime/combat.test.ts는 거부 불변성·전열/후열·빗나감·방어/강타/음식·0스태미나·도주실패/성공·승리 지급1회·패배 사건·턴 시간 상한·진행/종료 저장/재생·v5변환·손상 복원 원자성·실시간/오프라인 정지·기존 습격 연결·거점 체력 회복을 검사한다. content/combat.test.ts는 몬스터/조우/전리품/배치 참조와 수치 범위를 검사한다.


## D-042 기록·카메라 회귀

runtime/recent-records.test.ts는 이동/틱/자동 회복 제외, 상자 물품/현실 시각1회, 저장·복원,100개 상한/시계 역행의 사건 순서, v6→v7 및 손상 파일 원자 거부를 검사한다. UI 검사는 현지 HH:mm과 마법사만 마나 표시/저장을 확인한다.

browser-records.mjs는 제품 UI로106번 장착/해제 후100개 상한·실제 IndexedDB/새로고침·HH:mm·이동 기록 없음·지도 휠 팬 차단/확대 높이를 PC1440/모바일390/320px에서 검사한다. 기존 전투/아이템/파일/큰 맵 검사를 유지한다. 카메라 내부 구현은 프로그램 스크롤을 사용하지만 탐험 지도에서 사용자 스크롤은 차단하고 스크롤바를 숨긴다. 합성 큰 맵의 먼 좌표 강제 스크롤은 가상화 검사용이다.


## D-043 벽 타일 경계

browser-walls.mjs는 제품의 안전 구역을 실제 이동해 위/왼쪽 벽과 아래/오른쪽 모서리를 확인한다. 벽 셀의 바닥 채움은 없고, 내부 회색 벽 오브젝트는 바닥/플레이어와 같은 셀 크기임을 확인한다. 벽 충돌·지나온 경계/모서리 연결·PC/모바일 캡처를 포함한다. 큰 맵의 미탐사 칸에는 벽 오브젝트가 없어야 한다. visibility/App 검사는1칸 경계·모서리/다른 맵·층 분리/한 겹 너머 숨김·벽을 탐사 수에 더하지 않음을 검사한다. 경계가 보이는 규칙은 D-040 대신 최신 D-043을 따른다.


## D-044 모바일 한 화면 배치

`browser-mobile.mjs`는 배포 빌드를 같은 모바일 세션에서390×844→650→844,320×568,360×640,430×932,740×360,568×320,844×390,932×430으로 바꾼다. 문서의 가로/세로 넘침과 스크롤 위치, 상태/지도/상황/명령/기록/탭의 화면 경계·서로 겹침, 버튼44px 이상, 플레이어 추적을 확인한다. safe area는 CSS 변수로 위24/아래34px 및 가로 아래20px을 주입해 실제 레이아웃 공간을 검증한다. 가상화된 브라우저는 실제 노치/주소창 애니메이션을 재현하지 않는다.

작은 화면+safe area에서 실제 상자 탭/획득 품목·최근 기록과 조작부가 함께 보이는지 검사한다. 가로 소지품과 설정의 내부 스크롤·탭 복귀·지도 휠 후 문서 고정을 확인한다. 전체 제품/큰 맵 회귀와 같이 실행되며 `mobile-fit-*.png`와 `results.json`은 artifacts/browser에 남긴다. 캡처 육안 확인과 실제 사용자 폰 확인은 구분한다.


## T1 제작자 맵 생성기 (D-045)

`tools/map-generator.test.ts`는 동일 설정/시드 재현과 v1 JSON 해시, 다른 시드,12개 시드의 외벽/안전 시작/연결,9×9~512×512 및 방128개, 막다른 가지/추가 연결, 불가능한 설정·시드, 실제 CLI 출력/기존 파일 보존/검증 CLI를 검사한다. 제작자 전용 단일 층/안전 시작 제한과 원본 배치 보존도 확인한다. `content/map-reachability.test.ts`는 대각선/행 끝 연결 금지·고립 지형·셀 순서 독립성·다른 층 내부 검사를 포함한다.

`browser-maker.mjs`는 배포된 `/map-maker.html`에서1440/390/320px 생성·같은 설정 재생성·JSON 다운로드·수동 수정본 불러오기·실제 이동37칸/카메라·시작점 귀환·고립된 수정본의 원자 거부를 확인한다. 실제 기존 게임 슬롯을 먼저 저장하고 제작자 도구 사용 뒤 원문이 같은지 비교한다. PC에서512×512/방128개를 생성·불러와 이동하며 표시 DOM이2000개 미만임을 확인한다. `BROWSER_SUITE=maker`로 해당 범위만 실행할 수 있다. 기존 기본 게임/모바일 높이/128·512 합성 맵 검사도 유지한다.

화면/이동 시험의 캡처는 `artifacts/browser/maker-*.png`에 남긴다. 실제 사용자 기기/맵 디자인 확인은 자동 검사와 구분한다. CLI의 여러 Node 프로세스 시작은 병렬 전체 검사에서 느려질 수 있어 해당 통합 사례만15초 한도를 사용하며 각 자식 프로세스도10초로 제한한다.
