## 0. 목적 및 인계 순서

현재 메이커는 실제 JSON 생성·편집·시험·등록이 가능한 도구다. 디자인 개편은 **기능을 새로 추정해 만드는 작업이 아니라, 기존 작업 흐름을 더 알아보기 쉽게 재배치**하는 것이다.

1. GPT가 최신 `main`과 이 계약을 대조한다. 코드와 문서가 달라졌다면 실행 코드를 기준으로 변경 여부를 알리고 계약을 고친다.
2. Claude가 **맵 중심 작업면 + 상황별 편집 패널 + 명확한 검증/내보내기 흐름**을 디자인한다. 모형을 만들 수 있지만 제작자 엔진/검증 로직은 수정하지 않는다.
3. 사용자가 실제 제작 흐름으로 시안을 확인해 선택한다.
4. GPT가 승인 시안을 기존 `tools/**` UI에 적용하고 실제 생성·임포트·시험·등록 검증을 수행한다.
5. 두 에이전트 간에는 기준 커밋, 승인 시안/버전, 필드·액션 대응표, 편집 중 보호해야 하는 상태, 미지원 기능, 시험 결과를 인계한다. **동일 기능 브랜치의 병렬 수정은 금지**한다.

디자인이 신규 기능을 필요로 하면 'UI 제안'과 '실제 구현 범위'를 분리한다. 특히 초안 자동 저장/복원은 **아직 미구현**이므로 현재 동작으로 표현하지 않는다.

## 1. 실행 경로·코드 경계

- 양 메이커는 `src/ui/styles.css`와 `tools/map-maker.css`를 함께 사용한다. 게임/메이커 스타일 충돌이 생기지 않도록 메이커 CSS는 네임스페이스와 적용 범위를 분명히 해야 한다.
- `src/engine/**`, `src/content/**`, `src/persistence/**`, `src/runtime/**`와 `scripts/register-world.ts`는 디자인 담당이 변경하지 않는다. UI 개편에서 수정 요구가 생기면 GPT가 별도 기능/계약 PR로 검토한다.
- 컴포넌트 분리·접기/펼치기·폼 정렬·정보 구조 재설계는 허용하지만 ID 참조, 배치 가능 규칙, 생성 결과, 파일 형식, 오류 원자성, 저장 분리를 손상하지 않는다.
- 새로운 라이브러리, 디자인 시스템 패키지, 외부 이미지/폰트 CDN은 사용자 승인 전 도입 금지.

## 2. 맵 메이커 — 현재 화면/기능 재고

### 2.1 초기 작업·월드 관리

- 첫 화면은 `generateMap()`으로 만든 **새 임시 초안**을 표시한다. 기존 배포 게임의 맵을 자동으로 덮어쓰거나 불러오지 않는다. '현재 게임 맵 불러오기'는 명시적 버튼으로 실행한다.
- 맵/층 선택, **맵 생성(선택 맵 전체 교체)**, **새 맵으로 추가**, **층 추가**, **선택 맵 지형 복제**를 지원한다.
- 이름/ID/버전 수정은 **맵 정보 적용**을 누를 때 적용된다. 기존 맵 ID를 바꾼 뒤 배포 호환성을 자동 보장하는 것은 아니다.
- 시작 맵/거점의 **유효한 바닥 시작점** 지정, 층별 맵/좌표 선택을 유지한다.
- **되돌리기 20회**: 실제 편집 커밋 이전 상태로 복원한다. 이력과 현재 초안을 잃게 하는 UI 리팩터링 금지. 무제한 실행 취소나 되돌리기 이후 재실행(redo)은 현재 구현되지 않았다.
- 원본 초안과 지형 시험/게임 시험 진행은 별도 상태다. 시험을 종료하면 **편집 화면의 원본 그대로 복원**한다.

### 2.2 지도 캔버스·영역 편집

- `Overview`는 HTML canvas에 지형/시작점/몬스터/상자/출입구를 그린다. **선택 영역 오버레이는 별도 canvas**이며 선택 드래그마다 전체 지형을 다시 그릴 필요가 없다.
- 마우스/터치의 Pointer Events + pointer capture로 칸/사각형 영역을 지정한다. 클릭으로 1칸, 드래그로 여러 칸. X/Y 숫자로 칸 선택도 가능하다.
- 확대 선택은 **폭에 맞춤** / **12·24·48px/칸**. 큰 맵에서는 편집 캔버스 내부 스크롤이 가능하다. **512×512**까지의 제약·성능을 고려한다.
- 선택 영역에는 **영역을 바닥/벽/안전 구역/위험 구역으로** 4개 실행 버튼; 단일 칸에는 **바닥/벽/안전/위험** 편집이 있다. 편집 단위·되돌리기 의미를 혼동하지 않는다.
- 위험 지면 `#efadad`, 안전 지면 `#c9d9e2`, 벽 `#969696`; 몬스터 **원형**, 상자 채운 사각형, 출입구 테두리 사각형, 시작점 테두리. **위험/안전 색상은 사용자가 인지용으로 명시 지정한 기능적 색상**이므로 임의로 회색화하거나 던전 플레이 지도와 같게 만들지 않는다.
- 벽으로 바꾸면 충돌하는 배치/왕복 출입구를 제거하고 시작점은 보호한다. 안전 구역 변경은 몬스터 배치를 제거한다. 사라지는 항목/영향을 디자인에서 안내하는 것은 가능하지만 실제 동작을 바꾸지는 않는다.
- 새 브러시·다각형·영역 드래그 이동·레이어 눈금/잠금은 **현재 미지원**이다. 목업에는 '제안 기능'으로만 표시한다.

### 2.3 맵 간 문·계단·포탈

- 한 칸의 출입구 **문 / 계단 / 포탈**, 도착 **맵 ID·층·X·Y**를 지정한다.
- **왕복 출입구 연결**, **도착 맵 시작점과 연결**, **출발점 선택 → 다른 맵/층의 도착 칸 지정 → 연결**, **출입구 제거**를 모두 유지한다.
- 왕복 연결은 한쪽만 만드는 메뉴가 아니다. 기존 상대편과 충돌·고립 위험을 검사하고 편집 결과를 한 번에 반영해야 한다.
- 입구/목적지는 상자/몬스터 없는 유효 바닥이어야 하며, 출입구 연결/제거의 유효성 검사와 실제 맵 간 참조를 UI에서 우회하지 않는다.
- 걸어서 출입구에 도달한 뒤 게임에서는 **Z/Space 또는 이동 버튼으로 명시적으로 이동**한다. 밟자마자 자동 전환되는 것으로 시안에 묘사하지 않는다.

### 2.4 몬스터 배치·레벨·절차적 배치

- 몬스터 목록과 레벨을 고른 뒤 선택 칸에 개별 조우 ID를 배치한다. 같은 종류를 여러 칸에 둘 수 있지만, **각 조우 ID는 고유**해야 한다.
- 배치는 적이 없는 **위험 구역 바닥**에 한정하고 시작점·상자·출입구·기존 몬스터를 침범하지 않는다.
- 선택 칸의 적 레벨 적용, 전체 맵/선택 영역 내 **최소~최대 레벨 범위 적용**, 적 절차적 배치(시드·개수·최소 칸 간격·종류/범위)를 지원한다.
- 레벨 조정은 기본 몬스터의 **체력·최소/최대 피해·회복량**에 임시 비례식을 적용하며 원본 몬스터 ID를 덮어쓰지 않는다. 표시 숫자만 바꾸는 가짜 레벨 편집 금지.
- 절차적 배치는 동일 시드/초안/설정에서 결정론적이며 유효 빈 칸이 부족하면 **부분 배치하지 않고 전체 거부**한다.
- '몬스터 제작 화면 열기'는 별도 `/monster-maker.html` 링크, 생성 몬스터는 JSON으로 내보낸 뒤 맵 메이커의 **몬스터 불러오기**로 전달한다. 현재 두 탭 간 자동 동기화는 없다.

### 2.5 시험·검증·배포 내보내기

- **전체 검증**은 잘못된 지형/고립 구역/ID·배치/출입구 상호 참조를 보고한다. 편집 도중 미완성인 상태는 허용하되 시험·배포 단계에서 유효성 검사가 필요하다.
- 시험 범위: **자동(연결 완료면 전체, 미연결이면 현재 맵/층)** / **현재 맵·층만** / **전체 연결 맵 엄격 검증**. 기본 자동을 모든 맵 무조건 시험과 혼동하지 않는다.
- **걸어 보기:** 임시 Store의 지형·안개·이동 비용만 시험. 상자/몬스터는 지형 시험의 복사본에서 제외한다.
- **게임에서 시험:** 별도 Store로 실제 게임 UI·시간·아이템·전투 포함. '제작 화면으로' 복귀 시 시험 루프 종료, 편집 초안은 유지.
- **JSON 내려받기:** 단일 맵은 기존 배열 형태, 여러 맵/층·사용자 몬스터/조우가 있으면 묶음. **배포용 맵 묶음 내보내기**는 등록 가능한 world bundle 생성.
- **수정한 JSON 불러오기:** 기존 맵 배열 또는 묶음 지원. 잘못된 파일/참조/형식은 **기존 초안을 교체하지 않고 실패를 해당 입력 근처에 표시**.
- **배포 반영과 내보내기를 분리:** JSON 저장만으로 실제 게임이 바뀌지 않는다. `npm run register:world -- --file <file>`은 검사 전용, `--apply`는 변경 전 백업 후 등록한다. 기존 맵·몬스터 정의/세이브 호환 보호를 무시하는 '즉시 게임 적용' 버튼 추가 금지.

## 3. 몬스터 메이커 — 현재 화면/기능 재고

### 3.1 기본 정의/편집

- 몬스터 ID, 이름, 아이콘 문자, 설명, 기본 의도 문구, 레벨, 체력, 최소/최대 피해, 명중 확률(0~1) 입력.
- **순차 반복**과 **조건·무작위 행동 묶음** 두 모드를 지원하며 둘의 JSON 행동 정의를 동시에 지정할 수 없다.
- **순차 반복:** 공격(피해 배율), 힘 모으기·대기, 방어(받는 피해 배율), 자가 회복(회복량); 행동 문구·순서 이동(위로)·추가/삭제. 첫 행동부터 한 턴에 하나씩 실행하며 끝나면 반복.
- **묶음 모드:** 묶음 이름, 조건, 가중치, 우선순위, 완료 후 재사용 대기 턴, 전투당 최대 사용, 단계별 행동/수치/문구/반복 횟수.
- 조건 선택은 **항상 / 자신의 체력 N% 미만 / 전투 N턴부터 / 매 N번째 턴**의 단일 조건. AND/OR 조건 편집은 현재 미지원.
- 그룹/단계 추가·삭제·단계 '위로' 이동, 예제 **'힘 모으기 2회 → 강공격'**, **'체력 50% 미만 → 대기·회복'** 제공.
- 그룹이 여러 개일 때 **조건이 맞는 가장 높은 우선순위** 후보 중 가중치로 추첨. 일단 선택된 그룹은 여러 턴에 걸쳐 **끝까지 실행**, 중간에 재추첨하지 않는다. **반복 수=연속 턴 수**, 한 턴의 공격 횟수가 아니다.
- 기존 그룹 상한 **32개**, 단계 상한 **32개/그룹·반복 포함 128턴**, 각 단계 반복 1~20. 실제 유효성 검사는 기존 Zod 스키마가 수행한다. UI가 제한을 임의 확대/삭제하면 안 된다.

### 3.2 JSON 왕복/고급 편집

- **몬스터 JSON 내보내기**는 `vigil-monsters-v1` 형식(몬스터 한 개 포함)을 내려받는다.
- **몬스터 JSON 불러오기**는 이 화면에서 **몬스터 한 개만** 편집한다. 여러 몬스터 묶음은 맵 메이커로 가져온다.
- 기존 ID와 다른 정의의 중복 사용은 게임 콘텐츠/맵 등록 충돌이 될 수 있으므로 새 ID를 요구한다. UI가 같은 ID를 덮어쓰도록 자동 변환하지 않는다.
- 고급 JSON 편집 `details`를 열어 전리품 등 전체 JSON을 수정하고 **'JSON을 제작 화면에 적용'** 버튼에서 Zod 검증한 뒤 폼 상태를 바꾼다.
- 일반 폼 변경과 고급 JSON 텍스트가 **항상 실시간 양방향 동기화되는 것은 아니다**. 디자인이 이를 실시간 미리보기로 표현하려면 추가 기능 구현으로 분리한다.
- **전용 전투 시뮬레이터는 현재 없음.** 실제 전투 확인은 몬스터 JSON → 맵 메이커 임포트/배치 → 게임에서 시험한다.

## 4. 공통 파일 불러오기·초안 보호 계약

### 현재 동작 (D-048 이후 T1 상태)

- `tools/file-import.tsx` 공통 파일 입력 3곳: **맵 JSON / 맵의 몬스터 JSON / 몬스터 제작 화면 JSON**.
- 파일 선택 시 native 선택 파일명을 보존하며, **불러오는 중 / 완료 / 실패**를 해당 필드 아래 즉시 표시한다. **같은 파일 다시 불러오기** 지원.
- 맵 파일 **64MB 이하**, 몬스터 파일 **2MB 이하**. UTF-8 BOM 허용. 빈 파일, JSON 구문 오류, 스키마·참조 오류는 명확히 거부한다.
- 편집 중 이미 다른 변경·파일을 반영했다면 **늦게 끝난 이전 파일 읽기가 최신 초안을 덮어쓰지 않아야 한다**. 새 입력 오류는 기존 초안을 보존한다. 오류를 페이지 최하단에만 표시하지 않는다.
- 제작자 **임시 초안은 새로고침 후 자동 복원되지 않는다.** JSON 내보내기로 수동 보존해야 한다. 게임 IndexedDB 저장 슬롯과 연결된 초안 저장은 없다.

### T2에 추가할 예정인 기능 (현재 미구현)

- C1 단계에서 공통 메이커 내비게이션, **제작 전용 IndexedDB 초안 자동 저장·복원**, 명확한 저장 상태/내보내기 안내를 추가할 계획이다.
- 새 저장은 **게임의 primary/backup/generation 슬롯을 절대 덮어쓰지 않는 독립 영역**에 둔다. 임시 시험 Store도 실제 플레이 저장과 연결하지 않는다.
- 자동 저장의 충돌 해결, 초기 초안 복원 시점, JSON 임포트와 저장된 초안의 우선순위는 설계/테스트가 필요한 **구현 사양**이지 현재 확정된 UI 동작이 아니다.
- 마을/NPC/퀘스트 메이커(후속 C2~C5)는 새로 만들 도구다. 현재 맵/몬스터 제작 화면에서 해당 편집 기능이 존재한다고 보여 주지 않는다.

## 5. 메이커 UI 재설계에 권장하는 정보 구조

'어디에 무엇을 편집하는가'를 직관적으로 하되 기존 명령을 보존한다. 다음은 **디자인 방향**이지 현재 구현된 별도 패널 구성이 아니다.

| 메이커 | 주 작업면 | 보조 패널/하단 작업 |
|---|---|---|
| 맵 | **큰 캔버스**, 확대·영역 선택, 시작점/적/출입구 오버레이 | 왼쪽 생성/맵·층 목록 + 오른쪽 선택 칸/영역 속성 + 시험·검증·내보내기 |
| 몬스터 | 몬스터 이름/수치와 **행동 그룹·순서 카드** | 조건/가중치/우선순위 요약, JSON 오류/내보내기·불러오기 |
| 향후 마을 | 장면 배경과 핫스팟 선택 | 장소/NPC/출입구와 연결된 콘텐츠 참조 |
| 향후 퀘스트 | 단계·목표/선행 관계 편집 | 수동 NPC 수락·보고, 보상·캠페인/개인 귀속, 연계 검증 |

- PC에서는 캔버스가 더 넓은 작업면을 차지하게 제안하고, 맵 선택·영역 지정·속성 편집·검증·시험을 탭/아코디언/패널로 정리해도 된다.
- 모바일에서는 지도/속성 편집을 전환 가능한 패널이나 시트로 제공하되 **선택 영역이 사라지거나 미저장 편집이 초기화되면 안 된다**. 제작 도구는 기본 게임과 달리 긴 폼/지도 내부 스크롤을 허용한다. 잘못된 고정 높이 때문에 마지막 '검증/내보내기' 버튼이 접근 불가해지지 않도록 한다.
- 최소 44×44px 터치 타깃, 키보드 접근 가능한 선택/폼, 포커스 표시, 실행 중/실패/완료 상태, 스크롤 위치와 선택 정보의 연속성 확보.
- 사각형 선택 좌표/영역 크기/현재 편집 대상/몬스터 레벨/연결 대상 ID를 **현재 컨텍스트와 함께 표시**한다. 불가한 조작은 이유를 문구/설명으로 제공한다.
- 사용자 지정 색 `#efadad`, `#c9d9e2`와 원형 적 기호는 맵 메이커 내에서 유지한다. 게임용 탐험 지도의 어두운 안개/회색 팔레트와 혼동하지 않는다.
- 디자인 파일이 새 브러시, 자동 레이아웃, 인라인 편집, 라이브 시뮬레이터를 제시하면 **'구현 필요' 배지/목록**으로 따로 기록하고 기존 지원 기능인 양 표시하지 않는다.

## 6. 디자인 산출물 및 두 에이전트 작업 계약

### Claude 산출물

1. **PC 맵 메이커(1440×900)**: 큰 캔버스, 생성/맵 목록, 단일 칸 vs 사각형 영역, 출입구 왕복 연결, 몬스터 배치, 검증/시험/내보내기 상태별 시안.
2. **모바일 맵 메이커(390px·320px)**: 터치 영역 선택, 확대/스크롤과 편집 속성 접근, 오류/파일 선택, 바닥/벽/안전·위험 도구가 접근 가능한 시안.
3. **PC·모바일 몬스터 메이커**: 일반 수치·순차 행동·묶음별 조건/가중치/우선순위/단계 반복, 파일 입력/고급 JSON 상태 시안.
4. **공통 UI 스펙**: 탐색·패널 계층·디자인 토큰·폼/버튼/선택/disabled/검증/오류/파일 재시도/미저장 상태, responsive 기준, 키보드 접근성.
5. **액션 대응표**: 시안의 각 버튼 → 실제 현행 기능(위 2~4절) → 실제 소스 파일/handler. **없는 기능은 '제안/미구현'**으로 표시.
6. **인계 기록**: 기준 코드 SHA, 시안 파일/버전, 사용자가 승인한 범위, 변경/생략/추가 요소, 손실 위험과 미결 사항.

### GPT 구현 경계

- 디자인 기준은 **사용자가 승인한 시안/명세의 버전**이다. UI 배치가 바뀌어도 `generateMap`, `connect`, `paintRegion`, `placeMonster`, `preparePreview`, `FileImport` 등 **기존 검증된 함수**를 호출한다.
- 순수 UI 리팩터링과 신규 초안 자동 저장, 신규 메이커(마을/NPC/퀘스트)는 **별도 PR**로 구분한다. C1~C6의 의존성과 사용자 확인을 따른다.
- 파일을 실제로 임포트하고 실행한 뒤 기능 일치 여부를 검사한다. 스크린샷만 닮았다는 이유로 완료라고 보고하지 않는다.
- CSS/컴포넌트 파일의 상호 간섭 방지, 메모리 상태/비동기 파일 경합·되돌리기 경로 보존, 스키마 검증 결과를 UI 오류에 정확히 전달하는지 확인한다.
- 게임 화면을 임의로 바꾸지 않는다. `tools/map-maker.tsx`의 '게임에서 시험'은 공용 게임 UI를 재사용하므로 새 게임 UI 디자인은 [play-ui-contract.md](./play-ui-contract.md)의 별도 승인을 따른다.
