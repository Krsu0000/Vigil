# play-ui-contract.md — 플레이 화면 UI 기능·디자인 인계 계약

**대상:** The Last Vigil 게임 플레이 화면 · PC/모바일 · Claude 디자인 → 사용자 승인 → GPT 구현/검증  
**작성:** 2026-10-21 · **코드 확인 기준:** `main` 커밋 `02166cdd14c018b4c9dd3be0d78a2611cfb4efec`  
**상태:** [현재 구현 계약 + UI 개편 요구]. 이 문서는 새로운 디자인을 확정하지 않는다. 이미 구현된 동작과 앞으로 바꿀 디자인을 구별한다.  
**관련:** [UI 기준](../ui-reference.md), [구조](../architecture.md), [검증](../verification.md), [기능 현황](../features.md), [CLAUDE.md](../../CLAUDE.md), [메이커 UI 계약](./make-ui-contract.md).

## 0. 이 문서를 쓰는 방법 / 에이전트 인계

1. **GPT(구현 담당):** 이 문서의 '현재 구현'과 코드가 맞는지 최신 커밋에서 확인하고, 디자인 작업 전에 차이가 있으면 먼저 기록한다.
2. **Claude(디자인 담당):** 사용자 요청과 이 계약을 바탕으로 데스크톱/모바일 시안, 컴포넌트 상태표, 인터랙션, 디자인 토큰을 제안한다. 기존 코드 상태에서 **존재하지 않는 기능을 동작하는 것처럼 보이지 않는다**.
3. **사용자:** 시안과 인터랙션의 시각적 결과를 승인한다. 사용자가 확정한 시안이 이 계약의 기본 디자인을 대체할 수 있지만, 게임 규칙 변경은 별도 승인이다.
4. **GPT:** 승인된 시안을 **현재 엔진에 연결**하고 실제 브라우저·타입·테스트로 검증한다. 두 에이전트가 같은 게임 실행 파일을 동시에 수정하지 않는다.
5. **Claude:** 구현 캡처와 시안을 비교해 레이아웃 차이를 보고한다. 실제 게임 동작/엔진의 판정은 GPT 검증과 사용자 플레이 테스트를 기준으로 한다.
6. **모든 인계:** 기준 Git 커밋, 수정 가능 파일, 변경 목록, 확인한 스크린샷/해상도, 미구현 항목, 테스트 결과를 함께 전달한다. **문서만 전달하고 말로 해석하는 것보다 코드·화면 상태를 함께 교환**한다.

> 이 계약은 코드 경계를 명확히 하기 위한 문서이며, Claude가 항상 디자인을 더 잘한다거나 어느 에이전트가 무오류라는 전제는 없다.

## 1. 책임 경계 및 변경 승인

| 구역 | 현재 소유자 / 코드 | 디자인 변경 시 지켜야 할 계약 |
|---|---|---|
| 엔진·상태 | `src/engine/**`, `src/content/**` | 게임 수치, 행동 가능 조건, 위치, 전투, 아이템, 안개, 시간/보상을 UI에서 재구현하지 않음 |
| Store·루프·입력 | `src/runtime/store.ts`, `loop.ts`, `input.ts` | `dispatch`/GameStore 결과를 사용. 입력 쿨다운·동작·시간 루프 유지. 런타임 수정을 디자인 명목으로 포함하지 않음 |
| 저장 | `src/persistence/**`, `src/runtime/auto-save.ts` | 저장 슬롯, 복원, 버전 변환/중복 지급 규칙 유지 |
| 게임 UI 조립 | `src/ui/MapScreen.tsx`, `App.tsx` | 표시·기존 핸들러/props 연결 중심. 탭/다이얼로그 열림 등 **일시적 UI 상태만** 로컬 상태로 관리 |
| 게임 화면 부품 | `src/ui/{StatusPanel,MapView,MiniMap,CombatPanel,InventoryPanel,GameDialog,SettingsDialog,SaveStatus,SaveFiles}.tsx` | 시각적 구조 변경 가능, 정보 원천·disabled·포커스·접근성·실제 행동 의미 유지 |
| 스타일·문구 | `src/ui/styles.css`, `src/ui/strings/index.ts` | 디자인 토큰/그리드/글꼴/문구 개선 가능. 기존 문구를 새 규칙·실재하지 않는 수치로 바꾸지 않음 |
| 제작자 화면 | `tools/**`, `map-maker.html`, `monster-maker.html` | 이 계약 범위 밖. [make-ui-contract.md](./make-ui-contract.md)를 따른다 |

- Claude가 실행 가능한 목업을 만들 경우 **독립된 샘플/별도 디자인 브랜치**에 둔다. 게임 엔진 파일과 `src/runtime/**`를 직접 수정하지 않는다.
- GPT는 필요한 UI 컴포넌트 추출·표현용 prop 설계를 진행할 수 있으나 엔진 공개 API, 세이브 형식, 신규 라이브러리/게임 규칙을 바꿔야 한다면 승인과 별도 PR이 필요하다(`CLAUDE.md` 7절).
- 화면의 예시 데이터는 **목업용 가상 값**임을 표기한다. 실제 게임에 연결할 때 하드코딩된 레벨·돈·시설·퀘스트·마나 값을 사용하지 않는다.
- 기존 디자인 참조인 `docs/ui-reference.md`의 Superdesign 캔버스는 **디자인 참고본**이다. 사용자 추가 요구가 우선이고, 캔버스에 접근할 수 없을 때 최신 상태를 봤다고 주장하지 않는다.

## 2. 현재 화면과 인터페이스 — 확인된 구현

### 2.1 플레이 진입·기본 배치

- `src/ui/App.tsx`가 초기 로딩/오류를 처리한 뒤 `MapScreen`을 렌더링한다.
- `MapScreen`은 `useSyncExternalStore`로 GameStore와 게임 루프 스냅샷을 구독한다. 게임 틱/스태미나/위치 같은 데이터는 컴포넌트가 별도 계산하거나 재생성하지 않는다.
- 상단 `.game-top`: 게임 제목 VIGIL, 전투/조우/진행/정지, 경과 틱, 방치 요약(현재 '없음'), 저장 상태(존재할 경우), 설정. 메이커 게임 시험에서는 '제작 화면으로' 버튼이 추가된다.
- PC의 `.game-columns`: 왼쪽 캐릭터/자원, 중앙 지역/지도/상황/명령/최근 기록, 오른쪽 미니맵/소지품/퀘스트/코덱스. PC 기본 열은 CSS 후반 규칙 기준 `220px / 남은 폭 / 248px`; 좁은 화면에는 별도 규칙이 있다.
- 모바일 하단 메뉴는 **탐험 / 소지품 / 캐릭터 / 거점 / 더보기** 5개. PC에서 탐험 외 탭은 `GameDialog`로 열고, 모바일은 `.tab-page`로 표시한다. 전투 중 탭 조작 불가.
- 현재 캐릭터 표시명은 **'이름 없는 감시자' 고정 UI**, 아직 캐릭터 생성 시스템이 아니다.

### 2.2 자원·상태

- `StatusPanel.tsx`의 `Vitals`: 체력·스태미나는 실제 상태를 표시한다. 정신력/오염도는 아직 `—`이며 `archetype==='mage'`일 때만 실제 마나 자원 표시 필드가 추가된다. '—'를 가짜 값이나 0/100으로 대체하지 않는다.
- 캐릭터 정보/장비/이번 여정과 최근 기록은 실제 데이터와 현재 구현 수준만 표시한다.
- 거점 탭은 **안전 구역에서의 회복·소지품 정리**에 한정되어 있다. 시설 업그레이드, 제작/방치 타이머 등은 아직 구현되지 않았다.
- 퀘스트·코덱스는 현재 **빈 상태**다. T2 퀘스트/NPC/마을 화면은 승인된 **미구현 계획**이며, 플레이 UI 목업에 넣더라도 '향후 화면'으로 분명히 표시한다.

### 2.3 지도·미니맵 (가장 강한 불변 계약)

- `src/ui/MapView.tsx`: 맵/층/플레이어 좌표, 탐험 기억(visited), 실제 보이는 지형, 열지 않은 상자, 토벌하지 않은 적, 문/계단/포탈을 **기존 콘텐츠**에서 읽는다.
- **안개/정보 보호:** 확인되지 않은 칸의 타일 이름·아이콘·벽 여부·적/물품 정보를 DOM에도 포함하지 않는다. 디자인 변경으로 `unexplored` 정보를 사전 렌더링하거나 CSS로만 숨기는 것은 금지.
- **벽:** 확인한 길의 외곽을 1칸 두께의 연결된 벽 타일로 표시한다. 현재 CSS `.wall-object` 배경 `#969696`, 미탐사 배경 `#202020`, 보이는 바닥 `#626262` 등 D-043 기준을 유지하되, 사용자 승인 시 **색상만** 바꿀 수 있다. 벽과 바닥의 이동 판정·안개 판정은 바꾸지 않는다.
- **적 표식:** 게임 탐험 지도의 적은 원(`●`), 상자는 상자 기호, 출입구는 유형별 기호, 플레이어는 별도 표기. 제작기 표식과 혼동하지 않는다.
- **카메라:** 일반 탐험은 이동/화면 크기 변화에 따라 캐릭터 중심으로 추적하며 수동 팬/스크롤하지 않는다. `M` 전체 지도에서만 둘러볼 수 있다. 미니맵은 탐사된 지형·플레이어·현재 보이는 범위를 표시하고 클릭 시 전체 지도.
- **대형 맵:** 128×128·512×512 등에서 지도를 **전체 타일 DOM으로 렌더링하지 않는다.** `map-window.ts`의 표시 영역 계산과 `MapView` memo 및 좌표 조회 최적화를 유지한다. 리디자인으로 매 틱 지도 전체를 다시 렌더링하지 않는다.
- 한 화면에 표시되는 맵 크기나 CSS 확대는 조정할 수 있지만 **공개된 지형/접근성 의미·캐릭터 위치·아이템/몬스터 표시의 정확성은 유지**한다.

### 2.4 플레이 입력과 행동

| 입력/컨트롤 | 현재 실제 동작·연결 | 절대 변경하지 않을 의미 |
|---|---|---|
| 화살표 / WASD | `bindMovementKeys` → `loop.move(direction)` | 기존 100ms 이동 입력 경계/행동 비용, 게임 자체의 길게 누르기 반복 타이머 없음 |
| 화면 방향 버튼 | 주 포인터의 `pointerdown` 1회 이동, 키보드 활성화 `click(detail=0)` 지원 | `click`과 중복 이동 금지, 길게 누르기 자동 연속 이동 **재도입 금지**(D-036) |
| Z / Space | 현재 위치의 상자 열기 또는 출입구를 통한 `loop.travel()` | 출입구는 밟는 즉시 전환되지 않음; 조우/전투 중 불가 |
| R | 휴식 시작/종료(`loop.setResting`) | 가능 조건/습격 위험/회복 속도는 엔진 결정 |
| B | 즉시 거점 귀환(`loop.returnToCamp`) | 조우·전투 중 거부, 추가 비용 도입 금지(D-035) |
| I / C / M | 소지품 탭 / 캐릭터 탭 / 전체 지도 | 현재 키와 열린 창 안의 키보드 조작 유지 |
| Escape | 설정 열기 (상태에 따른 일시정지/재개 경로) | 설정과 게임 루프를 임의 중단하지 않음 |
| 설정·저장/파일 | `SettingsDialog`, `SaveStatus`, `SaveFiles` | 검증된 백업/불러오기 미리보기/명시적 적용 경로 보존 |

- 입력 요소, 모달, 링크, 버튼, IME 입력 중에는 단축키 충돌이 없어야 한다.
- 허용되지 않는 행동은 엔진/루프의 거부 결과를 따른다. 디자인을 위해 disabled를 임의로 제거하거나 UI가 상태를 직접 바꾸지 않는다.
- 상자 수령 후에는 **실제 획득 품목/수량**을 보여 주며, 이미 연 상자는 다시 보상을 주지 않는다. 출입구·상자 상호작용 버튼은 조건에 따라 중앙 상황 영역에 나온다.

### 2.5 전투·조우의 상태별 화면

- `pendingAmbush`: 조우 모달에서 **전투 시작 / 도주 시도**. 닫힌 미처리 조우는 재열기 UI가 있다.
- `CombatPanel.tsx`: PC 오른쪽 패널(기준 480px), 모바일 지도 아래 전투 시트. 활성 전투에서는 적 이름·설명·HP·전열/후열, 행동 의도(조건형 묶음 포함), 턴·전투 로그·플레이어 자원·행동을 표시한다.
- 전투 조작은 **공격 / 방어 / 기술(강타) / 아이템 / 도주**. 공격 타깃은 **살아 있는 전열 적 우선**, 후열은 조건에 따라 비활성화. 기술 사용 가능 조건과 아이템 사용 가능 여부는 코드 결과를 따른다.
- 몬스터 행동 묶음의 아직 뽑히지 않은 다음 행동을 **확정된 의도처럼 미리 말하지 않는다**. 뽑힌 뒤 단계가 정해졌을 때만 알려 준다.
- 조우·전투 중 탐험 지도/하단 탭·일반 소지품 행동을 막는다. 전투 중 시간/회복의 동작과 종료 틱 정산은 기존 엔진에 위임한다.
- 결과 화면은 승리/도주/패배에 따라 달라진다. 승리 전리품은 실제 결과에서, 계속 탐험은 가능한 결과에서만 보인다. **패배 후 새 캐릭터 계승 UI는 현재 미구현(S6)**.

### 2.6 기록·저장

- 최근 기록은 실제 `campaign.recentRecords`, 최대 **100개**가 저장되고 이동은 기록에 포함하지 않는다. 표시 시 접속자의 현지 시각 `HH:mm`을 사용한다.
- 탐험 화면에는 PC 최근 8개, 모바일 최근 2개를 노출하고 캐릭터→기록에서 전체를 볼 수 있다. 화면 레이아웃 개선으로 줄 수를 바꾸려면 기록 자체나 시간순서를 지우지 않는다.
- 자동 저장 상태는 성공/오류/저장 불가/백업 복구를 정확히 보여 준다. 모바일에서 정상이면 숨길 수 있어도 **경고를 숨겨서는 안 된다**.
- 설정의 저장 내보내기/파일 가져오기·미리보기·명시 적용과 오류 시 현재 진행 유지, 과거 세이브 마이그레이션은 기능 유지.

| 기준 | 현재 사실 | 디자인이 변경 가능/필수인 점 |
|---|---|---|

## 4. 디자인 산출물 계약 — Claude에게 요청할 것

## 5. 구현·검증 완료 조건 — GPT에게 요청할 것

### 자동/브라우저

- 기존 핵심: 이동 99/100ms 경계, 키보드/포인터 중복 입력과 자동 반복 미도입, 상자·포탈, 휴식·귀환, 전투 다섯 행동/대상/전리품, 정지, 저장·파일 교환.
- 맵: 미탐사 정보 누출 없음, 주변 벽만 정상 표시, 128×128/512×512 지도에 전체 DOM 확장 없음, 카메라 중심/미니맵 가시 범위가 맞음.
- 크기: 1440×900, 390×844, 320px 및 짧은 가로 화면에서 가로 넘침·기본 탐험 문서 스크롤·콘솔 오류 없음. 전투 시트·모달은 정상 접근/내부 스크롤.
- 코드 검증: 변경 관련 Vitest 우선, 마지막 `npm run typecheck`, `npm test`, `npm run build`(콘텐츠 수정 시 `npm run validate:content`), 필요한 `npm run test:browser`. 브라우저 실행 환경이 없으면 **미검증**으로 기록하며 통과라고 하지 않는다.
- 기존 결과(2026-10-16 `docs/progress.md`의 779개/55파일과 브라우저 결과)는 **과거 기준선**이지 새 UI가 통과했다는 증거가 아니다.

### 사용자 플레이

- 실제 휴대폰에서 기본 탐험 화면의 버튼이 모두 보이고 누르기 쉬우며, 스크롤 없이 지도와 현재 상황을 볼 수 있다.
