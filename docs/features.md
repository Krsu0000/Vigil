# features.md — The Last Vigil 구현 기능 명세

**실제로 구현된** 기능의 현재 동작을 기록한다. 계획은 `docs/roadmap.md`, 게임 규칙의 원본은 `docs/game-design.md`, 구조는 `docs/architecture.md`가 기준이다.

## 0. 이 문서의 규칙

- 코드와 테스트가 있는 기능만 적는다. 계획만 있는 기능은 적지 않는다.
- 기능의 동작이 바뀌면 같은 작업 안에서 이 문서를 고친다.
- 명세와 다르게 구현된 부분(임시 처리, 단순화)은 '명세와의 차이'에 반드시 적는다.
- 작동 규칙은 실제 코드가 하는 일을 적는다. 명세의 문장을 그대로 옮기지 않는다.
- 테스트 현황은 실제로 실행한 결과만 적는다.

### 구현 상태 표기

| 표기 | 의미 |
|---|---|
| `완료` | 완료 기준을 충족했고, 관련 테스트가 통과한다 |
| `부분 완료` | 일부만 동작한다. 빠진 부분을 '알려진 제한사항'에 적는다 |
| `미검증` | 코드는 있지만 테스트나 직접 확인을 하지 못했다 |
| `임시` | 다음 단계에서 교체될 임시 구현이다 (예: S2의 습격 팝업 임시 선택지) |

## 3. 기능 상세

### 코어 기초: 난수·수치 수정치·UUID

- **상태:** 완료
- **단계:** S0 두 번째 단위
- **관련 명세:** game-design.md 11.4·15.9절, decisions.md D-007·D-008
- **관련 코드:** `src/engine/core/rng.ts`, `modifiers.ts`, `id.ts`, 각 테스트, `src/engine/purity.test.ts`

**작동 규칙**

- 난수는 sfc32이며 시드 정수 4개를 검증한 뒤 첫 출력 15개를 버린다. 현재 상태를 저장·복원하면 같은 수열을 이어 간다.
- 정수 난수의 범위는 양끝을 포함하며, 치우침을 만드는 구간의 값은 버리고 다시 뽑는다.
- 수치 수정치는 기본값 → add 합산 → mul 곱셈 → 반올림 → 최소·최대 제한 순이다. add·mul 값은 정렬해 순서 차이에 따른 오차를 막는다.
- UUID v4 형식의 ID는 시드 난수 4개를 소비해 만든다.

**다른 시스템과의 연결**

- 캠페인 생성과 행동 처리에서 같은 난수 생성기·상태 형식을 사용한다. 수정치 수집은 이후 각 시스템이 맡는다.

**불변 조건**

- INV-17·INV-18. 결정론의 기초를 제공한다.

**테스트 현황**

- S1 두 번째 단위에서 전체 18개 파일·272개 테스트를 실행해 통과했다(2026-10-14, Node 22.22.0). 타입 검사·빌드·콘텐츠 검증도 통과했다.

**명세와의 차이**

- 없음.

**알려진 제한사항**

- 순수성 검사는 문자열 검색이며 주석도 검사한다. `computeValue`에 같은 target의 수정치만 전달하는 일은 호출자 책임이다.

### 코어 계약: 상태·캠페인 생성·행동 처리·효과

- **상태:** 완료
- **단계:** S0 세 번째 단위
- **관련 명세:** game-design.md 2.2·11.4·15.4·15.5·15.9절, architecture.md 2.2·3.1·3.2·7.1절, decisions.md D-017
- **관련 코드:** `src/engine/core/state.ts`, `actions.ts`, `events.ts`, `context.ts`, `campaign.ts`, `dispatch.ts`, `effects.ts`, `src/content/types.ts`, 코어 테스트와 `test-fixtures.ts`

**작동 규칙**

- `GameState`는 meta·campaign·character·expedition으로 나뉜다. S1에서 campaign.exploration과 character.position을 추가했다. 원정 상태는 아직 비어 있다.
- `createCampaign(content, seed, now)`는 campaign.exploration을 빈 객체로, character·expedition을 null로 만든다. gameTime은 0, lastActiveAt·settledUntil은 now다. now는 0 이상의 안전한 정수여야 한다.
- 캠페인 ID 생성 후의 난수 상태를 저장한다. 입력 시드·콘텐츠를 변경하지 않는다.
- `createDispatcher(handlers)`는 시작 시 전달받은 목록과 각 처리기를 복사·동결한다. 이후 원본 목록·처리기의 변경은 이미 만든 함수에 영향을 주지 않는다.
- 행동 종류를 찾고 조건을 검증한 뒤에만 난수 생성기와 execute를 실행한다. 거부된 행동은 원본 상태와 같은 참조를 반환한다.
- 성공한 행동은 처리기가 반환한 상태·사건을 사용하고, rngState는 실제 생성기의 최종 상태로 기록한다.
- 행동·사건의 구체적인 유니온은 시스템이 정의한다. 현재 제품의 기본 dispatch에는 게임 처리기가 없다.
- 효과는 Zod 스키마와 적용 함수를 묶어 등록한다. 레지스트리 검증 함수는 미등록 유형과 잘못된 매개변수를 구분해 반환한다. 직접 적용하더라도 검증 실패 시 실행하지 않는다.
- 효과 적용에는 Zod로 파싱한 매개변수를 전달한다. 코드 예외는 일반 행동 거부로 변환하지 않는다.

**다른 시스템과의 연결**

- `EngineContext`로 콘텐츠와 행동 시각을 받는다. ContentDb는 네 번째 단위에서 버전·시간 규칙·정의 배열·ID 조회로 확장됐다.
- 이후 연결부가 시스템별 처리기를 조합해 dispatch를 만든다. 코어가 시스템을 import하지 않는다.
- 콘텐츠 로더는 효과 레지스트리의 검증 함수를 호출한다.

**불변 조건**

- INV-02·INV-04·INV-05·INV-17. INV-16의 콘텐츠 연결 검증은 네 번째 단위에서 완료했다.

**테스트 현황**

- S1 두 번째 단위에서 전체 18개 파일·272개 테스트 통과(2026-10-14, Node 22.22.0).
- `npm run typecheck`, `npm run build`, `npm run validate:content` 통과. 콘텐츠 검증은 실제 JSON 5개의 스키마·참조·의존·효과·맵 배치까지 검사한다.
- 중첩 동결 상태를 이용해 원본 보존을 확인하고, 생성 → 행동 → 효과 → 사건 → 난수 상태 기록과 JSON 복원 후 후속 행동 결과를 검증했다.
- 화면 변경 없음. 이번 단위의 별도 수동 플레이 검증은 없다.

**명세와의 차이**

- 코어의 Action·GameEvent는 공통 형태이며, 시스템별 유니온을 생성 함수의 타입 인수로 전달한다. 코어가 모든 시스템의 행동을 직접 import하지 않기 위한 방식이다(D-017).

**알려진 제한사항**

- map/start·move/step과 맵 시작점 배치가 구현됐다. 실제 게임 효과·캐릭터 능력치는 아직 없다. 브라우저 저장은 아래 S3 첫 단위에서 연결했다. GameStore와 맵 UI는 S1 세 번째 단위에서 연결했다. 콘텐츠 로더·참조 검증은 네 번째 단위에서 추가했다.
- `createCampaign`의 content 인수는 초기화 계산에 사용하지 않는다. 최초 프로토타입 위치 배치는 map/start로 한다. 콘텐츠 정의는 상태에 복사하지 않는다.
- 테스트용 효과는 테스트 구성에서만 등록한다. 불변성은 읽기 전용 타입과 테스트로 확인하며 제품 실행마다 상태 전체를 동결하지 않는다.

### 콘텐츠 기반·검증·시작 시 오류 안내

- **상태:** 완료
- **단계:** S0 네 번째 단위
- **관련 명세:** game-design.md 11.4·14.5·15.5절, architecture.md 6장, decisions.md D-011·D-014·D-019
- **관련 코드:** `src/content/manifest.json`, `time-rules.json`, `schemas.ts`, `types.ts`, `load.ts`, `scripts/validate-content.ts`, `src/runtime/content.ts`, React 진입점과 오류 안내

**작동 규칙**

- 실제 JSON은 매니페스트·시간 규칙·타일·구역·맵의 5개다. 현재 버전은 0.2.5이며 기존 시간·스태미나 값과 이동 간격 100ms(D-032)를 사용한다.
- 파일·스키마 검증 → ID 중복·참조 존재 확인 → 효과 검증 → 맵 배치 검증 → 선행 의존 순환 검증 순으로 진행한다. 하나라도 실패하면 부분 DB를 반환하지 않는다.
- 필수 파일 누락, 중복 파일, 목록 외 JSON, 잘못된 ID·수치, 누락 참조, dependsOn 순환, 미등록 효과·잘못된 매개변수가 오류다.
- references는 존재만 확인해 상호 연결을 허용한다. dependsOn은 순환을 허용하지 않는 선행 의존이다.
- 통과한 데이터는 ID별 조회를 제공하며 입력과 분리하고 중첩까지 고정한다. 효과 매개변수도 복사해 입력 변경이 이미 검증한 데이터에 영향을 주지 않는다.
- 브라우저는 Vite로, CLI는 파일 시스템으로 전체 JSON을 수집한다. 같은 로더와 제품 효과 레지스트리 검증 함수를 사용하며 로딩 중 효과를 실행하지 않는다.
- 정상 데이터는 GameStore를 초기화하고 탐험 맵을 표시한다. 콘텐츠가 잘못되면 파일·필드 위치가 포함된 오류 안내를 표시한다. 오류 문구는 React 텍스트로 표시한다.
- CLI는 성공 시 0, 오류 시 1로 종료한다. 콘텐츠 폴더가 없거나 비어 있는 경우도 오류다.

**다른 시스템과의 연결**

- ContentDb는 버전·시간 규칙·정의 배열·ID 조회 사전이다. 코어 테스트의 연결용 콘텐츠도 이 실제 계약을 사용한다.
- 실제 게임 정의와 효과는 각 시스템 도입 시 추가한다. 데이터는 engine을 import하지 않으며 연결부에서 효과 검증을 주입한다.

**불변 조건**

- INV-15·INV-16. INV-15는 공통 외피와 맵의 실제 배치 참조 검증을 포함한다. 아이템 등 다른 정의의 실제 필드 참조는 각 시스템 도입 시 추가한다.

**테스트 현황**

- S1 두 번째 단위에서 전체 18개 파일·272개 테스트 통과(2026-10-14, Node 22.22.0). 기존 코어 회귀와 3,000개 정의의 의존 관계 검증 포함.
- 타입 검사·빌드·콘텐츠 검증 통과. 실제 JSON 파일 5개, 오류 0개.
- 실제 Node CLI의 정상·오류 종료 코드 0·1을 검증했다.
- 브라우저 자동 검증: 정상·잘못된 시간 규칙 각각 1280px·390px 화면에서 제목·오류 표시·오류 위치·가로 넘침·실행 중 예외를 확인했다.
- 위 브라우저 자동 검증은 네 번째 단위에서 수행했다. S1 첫 단위에서는 브라우저·실제 폰·Pages 배포를 재확인하지 않았다. Vite의 실제 JSON 수집·검증은 런타임 연결 테스트로 확인했다. S0의 Pages·폰 제목 표시는 첫 단위의 사용자 확인 기록을 따른다.

**명세와의 차이**

- 없음. 공통 정의 외피와 현재 구현한 검증 범위는 D-019에 기록했다.

**알려진 제한사항**

- 맵·타일·구역의 구체 스키마가 추가됐다. 아이템·몬스터 등 다른 정의의 구체 스키마와 게임 효과는 아직 없다.
- 이 런타임 파일은 콘텐츠 연결만 담당한다. 상태 생성·GameStore는 runtime/store.ts와 진입점에 연결됐고 틱 루프는 S2다.


### 저장 계약: SaveFile v4·메모리 왕복·v1/v2/v3 변환

### GameStore·맵 화면·키보드/모바일 조작

- **상태:** 완료 (S1 마감 수용)
- **단계:** S1 세 번째 단위
- **관련 명세:** architecture.md 1.2·3.3·9장, decisions.md D-023
- **관련 코드:** `src/runtime/store.ts`, `input.ts`, `src/main.tsx`, `src/ui/MapScreen.tsx`, `styles.css`, `strings/index.ts`

**작동 규칙**

- 콘텐츠 검증 후 새 GameStore를 한 번 생성해 map/start로 시작점에 배치한다. 시작 맵은 콘텐츠에 정확히 1개 있어야 한다. StrictMode의 화면 재실행은 캠페인을 다시 만들지 않는다.

- 메모리 복원은 저장 검증·버전 변환·실제 맵 대조 후 교체한다. 실패하면 이전 상태와 구독을 유지한다. 미배치 복원은 자동 배치하지 않고 명시적인 탐험 시작 버튼을 제공한다.
- 맵은 회색조 CSS Grid다. 지도 배경·미탐사 칸은 짙은 회색, 확인한 벽은 검정색이다. 밟은 바닥·현재 시야·플레이어는 단계별 회색으로 구분하고 범례도 실제 배경색과 일치시켰다. 가려진 지형 정보는 DOM에도 넣지 않는다. 벽은 칸 전체를 채우고 타일 사이 간격은 없다.
- 현재 위치·탐사 수·구역 이름과 안전/위험 표시를 상태와 콘텐츠에서 계산한다. 방향키·WASD·모바일 버튼으로 이동한다. 버튼은 최소 44×44px이며 작은 화면에서도 맵과 조작부가 함께 보인다.
- 입력 필드·편집 영역·IME·수정키 조합은 이동하지 않는다. 리스너 해제로 StrictMode 중복 입력을 막는다. 현재 브라우저 저장과 거점 최대 24시간 오프라인 회복 안내를 표시한다. 저장소 불가 모드에서는 새로고침 초기화 안내를 표시한다.

### 실시간 틱·정지·하트비트·이동 간격

**작동 규칙**

- 사용자 승인(D-028)으로 전역 틱과 스태미나 회복 시점을 분리했다. 회복 안내는 최대치/대기/정지를 표시하고 틱 간격·회복 간격·회복량을 콘텐츠에서 읽는다.
- 전역 time/tick은 현재 2초마다 gameTime을 진행한다. 스태미나는 바꾸지 않는다. 성공한 이동도 전역 틱을 초기화하지 않는다.
- 마지막 성공 이동 후 recoveryIntervalMs(현재 2초)가 지나면 stamina/recover로 1 회복한다. 대기가 계속되면 같은 간격마다 회복한다. 다시 이동하면 회복 대기만 새로 센다. 벽/자원 부족/입력 간격 거부는 대기를 초기화하지 않는다.
- 단일 타이머는 전역 틱·회복·하트비트의 가장 가까운 시점을 예약한다. 지연된 효과도 시간순으로 처리하고 동시에는 전역 틱→회복 순서다. 회복 자체는 게임 시간/난수/이동 표시를 바꾸지 않는다.
- 진행/정지/전투 상태를 표시한다. 상단 일시정지 버튼은 없고 설정창에서 틱·이동을 중단한다(D-040). 설정을 닫으면 공백 정지를 해제하고 새 주기로 재개하며 정지 구간/부분 틱은 소급하지 않는다. 루프의 수동 정지 API는 내부 검사에 남긴다.

- 새 시간 규칙 필드 추가 때 0.2.1로, 테스트 틱 2초 변경 때 0.2.2, 독립 회복 간격 추가 때 0.2.3, 습격 판정 준비 후 0.2.4, 입력 반응 임시값 조정 후 현재 contentVersion은 0.2.5다. 두 번째 단위에서 맵 버전 1·SaveFile v3·기존 예시/변환은 유지했고 세 번째 단위에서 SaveFile v4로 확장했다. 새 의존성은 없다.

### 입력 반응 개선 (사용자 지연 제보)

- **재현:** PR #15가 병합된 main 5c70327의 코드에서 150ms 간격 방향키 입력이 200ms 최소 이동 간격으로 거부됐다. 모바일은 touchStart/누름 중 위치가 바뀌지 않고 touchEnd/클릭 때 이동했다. 사용자의 특정 기기 성능 저하와 동일한 원인인지까지 확인한 것은 아니다.

### 길게 누르기 연속 이동 (D-033, 사용자 요청 D-036으로 제거됨)

- **범위:** PR #16 병합 후 사용자가 연타 개선을 확인하고 길게 누르기의 지연을 제보했다. 키보드와 화면 버튼 모두 처음 누를 때 즉시 이동을 시도하고, 누르는 동안 콘텐츠의 최소 이동 간격(현재 100ms)마다 시도한다. OS 반복 이벤트를 무시한다. 최소 이동 간격의 기존 100/200/500ms 검사는 유지한다.
- **종료/전환:** 마지막 누른 방향을 우선하고 해제하면 아직 누른 방향을 다음 간격부터 사용한다. 손을 떼기·포인터 취소/캡처 손실·창 이탈/화면 숨김·입력 필드 초점·다른 키 명령·정지/설정/습격·언마운트에서 해제한다. 벽/자원 부족도 반복을 해제하고 재입력을 기다린다. 자원 회복/설정 닫기/습격 해제만으로 움직이지 않는다. 지연된 이동을 몰아서 실행하거나 손을 뗀 뒤 예약 이동하지 않는다.
- **접근성/모바일:** pointer capture와 window 해제로 버튼 밖에서 손을 떼어도 정지한다. 버튼에 한해 터치 스크롤/텍스트 선택/길게 누르기 메뉴를 막는다. Enter/Space/보조기술 단일 click과 primary/왼쪽 버튼 규칙은 유지한다. 키보드/화면 버튼 안내 문구를 갱신했다.

### S3 세 번째 단위: 세이브 파일 교환 (D-034)

- **기능:** 설정창에서 파일로 내보내기/가져올 파일 선택 → 검증과 탐험 미리보기 → 명시적 교체 또는 취소. 파일 처리 중 닫기/ESC/중복 작업을 막는다. v1~v3도 기존 변환을 거치며 JSON 형식/버전/필드/현재 맵/활동 오류를 거부한다. 최대 10MiB이며 확장자에 의존하지 않는다.
- **내보내기:** 브라우저의 마지막 성공 쓰기뿐 아니라 현재 미저장 진행도 캡처한다. 실행분과 savedAt을 맞추고 saveId/마지막 성공 revision을 유지한다. 파일 생성만으로 브라우저 저장/revision 증가/오프라인 정산을 하지 않는다.
- **가져오기:** 후보만 오프라인 정산하고 현재 미저장 진행을 백업한 뒤 원자적 쓰기에 성공해야 활성 탐험을 교체한다. 파일 saveId/revision+1을 이어 쓰고 로컬 generation으로 다른 탭 충돌을 막는다. 실패 시 현재 상태/슬롯/저장 메타데이터를 유지한다. 기존 탐험의 저장 재시도와 후보 재적용은 다른 동작이다.
- **시간/제한:** 최대 24시간·시각 역행·위험지대 제외·습격 보존은 기존 규칙이다. 성공 후 이전 탐험의 실행 완료 시각/부분 주기/이동 제한을 초기화하고 수동/설정/공백 정지와 가져온 습격 제한은 유지한다. 같은 시각 재접속에서 재지급하지 않는다.
- **메모리/백업:** 저장소 불가 모드에서도 파일 교환을 허용하며 브라우저 백업 불가를 표시한다. 정상 모드의 이전 탐험 백업은 기존 회전 슬롯 1개이므로 계속 보관할 진행은 파일로 내보내도록 안내한다.
- **브라우저 검증:** 배포 빌드/실제 IndexedDB의 Chromium 1280/390/320px에서 실제 다운로드/업로드·취소/잘못된 파일 보존·미저장 현재 진행의 백업·정산 1회/즉시 재접속·용량 오류/재시도·두 탭 충돌을 확인했다. 한국어 폰트/320px 미리보기 육안 확인, 긴 파일명에서도 가로 넘침 없음·버튼 44px 이상·콘솔 오류 없음. 미래 실행 시각→역행→파일 교체→긴 공백의 새 정산, 가져온 습격 제한, v1 미배치 상태/설정 닫기, 저장소 불가 파일 교환도 확인했다.
- **판정/범위:** 콘텐츠 0.2.5/SaveFile v4/DB 1/기존 변환 유지. 최초 슬롯 복원 실패 화면의 파일 복구 UI는 추가하지 않았다. 실제 폰의 다운로드/파일 선택은 미검증이며 S2 재미/위험·S3 전체 완료와 구분한다. 최종 전체 559개/34개 파일·타입 검사·빌드 통과. 콘텐츠/세이브 스키마 미변경으로 콘텐츠 CLI는 생략했다.


### S3 네 번째 단위: 거점 즉시 귀환 (D-035)

- **기능/규칙:** 위험 구역에서 미처리 습격이 없으면 ‘거점으로 귀환’으로 단일 맵의 콘텐츠 시작 칸(임시 거점)으로 돌아간다. 스태미나 0에서도 가능하며 추가 비용/준비/게임 시간/재사용 대기는 없다. 안전 구역/미배치/미처리 습격/세션 정지에서는 사용할 수 없다. 불확정 다중 맵/위험한 시작 칸은 임의 목적지로 사용하지 않는다.

- **저장:** 기존 v4 자동 저장/파일 전송을 사용하고, 귀환 후 닫힌 시간에는 거점 오프라인 정산이 적용된다. 저장 실패 시 귀환한 메모리 상태를 유지하고 일반 저장 재시도로 저장한다. SaveFile/콘텐츠/코어/DB 구조 변경 없음.
- **브라우저 검증:** 배포 빌드/실제 IndexedDB의 Chromium 1280/390/320px에서 스태미나 0·즉시 회복/추가 틱 없음·새 주기 거점 회복·누른 입력 해제·휴식 종료·팝업 닫기 후 습격 차단/임시 도주 후 허용·수동/설정 정지·Enter/Space·자동 저장/새로고침/거점 오프라인·저장 실패/재시도·파일 내보내기를 확인했다. 한국어 폰트/320px 화면 육안 확인, 가로 넘침 없음·귀환 버튼 44px 이상·콘솔 오류 없음.

### T1 조건·랜덤 행동 묶음 (D-048)

- 몬스터 제작에서 ‘순차 반복’과 ‘조건·무작위 행동 묶음’을 선택한다. 일반 공격3/강공격1 같은 가중치와 우선순위, 체력/턴 조건, 재사용 대기·전투당 사용 횟수, 단계별 반복을 간편 폼으로 지정한다. 두 요청 예제는 버튼으로 추가한다.
- 조건을 만족한 최고 우선순위 후보에서 시드 가중치 추첨한다. 시작한 묶음은 한 턴에 한 행동씩 완료하고 다음 묶음을 다시 고른다. 대기2회→강공격,50%미만→대기→회복을 실제 전투에서 실행한다. 후보가 없으면 일반 공격한다.
- SaveFile8로 진행 중 묶음·반복·쿨다운/횟수·가드·난수를 보존하며 v1~v7을 변환한다. 초기 상태/행동 재생 검증으로 위조 상태와 새로고침을 통한 재추첨을 막는다. 기본/기존 순차 행동과 제품 콘텐츠는 유지한다. 전투 의도는 진행 중 다음 단계만 확정 표시한다.
- JSON 내보내기/다시 편집/맵 임포트/레벨 회복량 변형/등록 경로에 묶음을 포함한다. 조건 AND/OR·묶음 중간 강제 중단은 지원 범위 밖이다. 상세 의미/제한은 map-maker.md를 따른다.

### 제작자 JSON 불러오기 개선 `[구현됨]`

맵·몬스터 파일을 고른 직후 선택값을 비우던 처리를 제거했다. 각 입력 아래에 파일명/읽는 중/완료/오류를 표시하고 같은 파일 재시도 버튼을 제공한다. UTF-8 BOM을 허용하며 빈 파일·구문 오류·용량 제한·기존 콘텐츠 검증 실패는 초안을 교체하지 않는다. 느린 이전 읽기가 최신 파일 선택을 덮어쓰지 않는다.
