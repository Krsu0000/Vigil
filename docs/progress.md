- 즉시 귀환·야영지 보호 만료·방치 작업 완료·실제 전투는 미구현이다. 귀환 제약은 아직 결정하지 않았다.

## 2. 이번 변경

- `persistence/file-transfer.ts`: 파일 크기 사전 제한 10MiB, UTF-8 BOM 처리, 기존 JSON/스키마/v1~v3 변환과 현재 맵/활동 검증. 파일 선택/미리보기/취소는 활성 상태나 저장소를 바꾸지 않는다.
- `runtime/auto-save.ts`: exportSave는 미처리 실행분을 반영해 현재 상태·현재 savedAt·파일 ID/마지막 성공 revision을 내보낸다. 다운로드 자체는 브라우저 쓰기/revision 증가/별도 정산을 하지 않는다.
- importSave는 기존 진행 중 쓰기를 기다리고 자동/숨김 쓰기를 차단한다. 별도 후보 Store에서 savedAt 이후를 정산하고, 미저장 현재 진행의 백업과 후보 primary를 세대 확인 트랜잭션 한 번으로 기록한다. 성공한 뒤에만 활성 상태·saveId/revision을 교체한다. 실패/충돌이면 기존 상태/슬롯/메타데이터를 유지한다.
- 가져온 파일은 saveId를 보존하고 revision+1·현재 savedAt/콘텐츠 버전으로 저장한다. 다음 자동 저장도 이 ID/revision을 이어 쓴다. 실패 후 일반 저장 재시도는 현재 탐험을 저장하며 후보를 적용하지 않는다.
- `runtime/loop.ts`와 `main.tsx`: 성공 후 resetAfterRestore로 이전 탐험의 실행 완료 시각·부분 틱/회복·이동 제한을 초기화한다. 수동/설정/공백 정지와 새 습격 제한은 유지한다. 기존 탐험에서 미래 시각을 경험했어도 가져온 탐험의 이후 정산을 누락하지 않는다.
- `ui/SaveFiles.tsx`·설정창/App/MapScreen·문구/CSS: 다운로드, 파일 선택, 시각/게임 시간/스태미나 미리보기, 교체/취소, 성공/오류 표시. 처리 중 닫기/ESC/중복 작업을 막는다. 이전 미배치 파일도 설정창을 닫을 수 있다.
- 저장소 불가 모드도 메모리 파일 교환을 허용하고 브라우저 저장/백업 불가를 명시한다. 정상 백업은 기존 회전 슬롯 1개이며 이후 자동 저장으로 갱신됨을 안내한다.

## 4. 사용자 확인·제한

- 최초 실제 폰 정상 이동, PR #16 후 연타 개선은 사용자 확인 완료다. 100ms 유지 동의와 실제 기기의 길게 누르기/파일 교환 검증을 구분한다.
- 최근 휴식/습격·저장/거점 정산의 실제 폰 확인 및 S2 재미/위험 평가는 미확인이다. 자동 브라우저의 모바일 크기는 실제 폰 검증이 아니다.

- 백업 1개는 영구 보관이 아니다. 이전 탐험을 계속 보관하려면 파일로 내보낸다. 저장소 불가 모드의 가져오기는 메모리만 교체하므로 새로고침 전 파일로 보관해야 한다.
- 폰 강제 종료/백그라운드에서 쓰기 완료는 미검증이며 최근 1초 변경은 유실될 수 있다. main/미리보기는 저장소를 공유하지 않지만 JSON 파일로 옮길 수 있다.
- 콘텐츠 버전별 추가 변환/서버 동기화는 없다. SaveFile 형식·코어·회복/비용/습격 규칙은 바꾸지 않았다. GPT에서 구현/검증했으며 Claude Code로 넘길 필요는 확인되지 않았다.
