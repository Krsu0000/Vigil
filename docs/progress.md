## 2. 이번 변경

- `engine/systems/map/selectors.ts`: getReturnDestination은 현재 위험 구역/미처리 습격 없음/단일 맵에서 콘텐츠의 시작 칸을 선택한다. 도착 칸의 이동 가능/안전 여부를 검사하며 다중 맵 중 첫 항목이나 위험한 시작 칸을 임의 목적지로 고르지 않는다.
- `map/return`: 위치를 거점으로 옮기고 활동을 waiting으로, 이동 표시를 true로 바꾼다. 자원·기존 탐사·게임 시간/시각/난수·원정은 유지한다. 가져온 유효 상태에 도착 칸 기록이 없다면 그 칸만 추가하고 중간 경로는 공개하지 않는다. map/returned 사건을 낸다.
- `loop.returnToCamp`: 기존 마감 틱/습격을 먼저 처리하고 세션 정지를 검사한다. 성공 뒤 회복 대기만 새로 세고 전역 틱/하트비트는 유지한다. 스태미나 0 허용, 추가 비용/준비/게임 시간/재사용 대기 없음. 일반 이동의 쿨다운으로 귀환을 막거나 귀환으로 이동 간격을 새로 소비하지 않는다.
- MapScreen/문구/CSS: ‘거점으로 귀환’ 버튼과 상태별 안내를 추가했다. 귀환 시 누른 이동 입력을 지워 도착 후 자동으로 걸어 나가지 않게 한다. 안전 구역/미처리 습격/세션 정지에서 비활성화하며 자원을 즉시 회복시키지 않는다.
- 기존 Store·v4 자동 저장·파일 전송·거점 오프라인 정산을 재사용한다. 귀환 후 저장 실패는 기존 정책대로 메모리의 귀환 결과를 유지하고 명시적 저장 재시도로 기록한다.
- 승인된 규칙을 game-design 4.9/4.11/19, D-035, architecture/features/roadmap에 반영했다. 기존 ‘귀환 준비 몇 틱’ 제안은 채택하지 않는다.

## 4. 사용자 확인·제한

- 최초 실제 폰 정상 이동, PR #16 후 연타 개선은 사용자 확인 완료다. 100ms 유지 동의와 실제 기기의 길게 누르기/파일 교환/귀환 검증을 구분한다.
- 최근 휴식/습격·저장/거점 정산의 실제 폰 확인 및 S2 재미/위험 평가는 미확인이다. 모바일 크기 자동 브라우저 검사는 실제 폰 검증이 아니다.
- 현재 귀환 목적지는 단일 맵의 콘텐츠 시작 칸(임시 거점)이다. 다중 맵/거점 선택, 실제 전투 중 제한, 전투 도주와 귀환의 연결을 구현했다고 기록하지 않는다.
- 최초 슬롯 복원 실패 화면의 파일 복구 UI는 없다. 손상/미래 버전 슬롯 보호는 유지한다. 백업 1개는 이후 자동 저장으로 회전하므로 영구 보관은 파일 내보내기를 사용한다.
- 폰 강제 종료/백그라운드에서 저장 완료는 미검증이며 최근 1초 변경은 유실될 수 있다. main/미리보기는 저장소를 공유하지 않지만 JSON 파일로 옮길 수 있다.
- GPT에서 구현/검증했으며 Claude Code로 넘길 필요는 확인되지 않았다.
