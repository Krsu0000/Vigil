## 2. 이번 변경

- 콘텐츠 `item`/`chest` 구체적 스키마와 물품/배치/효과 검증. 제품 effect registry를 음식 실행/런타임 로더/CLI가 공유한다. 새 제품 의존성은 없다.
- `character.inventory`에 아이템 ID별 수량/발 슬롯, `campaign.openedChests`에 열린 상자 기록. 같은 칸의 상자를 열 때 전부 지급/열린 기록을 한 행동으로 처리하며 중복·실패는 상태와 난수를 보존한다.
- 보급 상자 (3,1): 여행 식량 3개/탐험용 장화 1개. 폐허 상자 (5,3): 식량 2개. 식량 한 개로 120 즉시 회복하며 최대치에서는 소비하지 않는다. 마지막 수량은 제거하고 휴식 중 최대치 도달 시 대기로 전환한다.
- 장화 장착 시 이동 비용 6→4/탐사 3→2/안전 0. 해제 시 복원한다. 장비 add 다음 탐사 배율을 기존 computeValue로 계산하며 표시/실제 차감이 같은 계산을 쓴다. 소지 중량은 장착품 포함 정수 g 합산/표시만 한다.
- 소지품 모달은 시간/회복/습격을 멈추지 않는다. 습격이 나면 기존 팝업으로 전환한다. 창 안의 화살표 키는 지도에 전달하지 않는다. 아이템 입력 전 마감된 시간 처리를 하며 정지/습격 중 조작을 차단한다.
- v4 스키마를 고정하고 v4→v5 변환을 추가했다. 슬롯/파일 복원 모두 실제 아이템·장착·상자 정의를 대조한 뒤 교체한다. 자동 저장/백업/내보내기·가져오기를 그대로 사용한다.
- 큰 맵의 한 칸 조회/표시 범위 렌더링을 유지한다. 상자는 칸의 chestId로 조회하며 전체 맵/상자 목록을 매 입력마다 돌지 않는다. 시간/회복/장착만 바뀌면 지도 재렌더링을 생략한다.

## 4. 남은 한계

- 현재 상자는 캠페인에서 한 번 열린 기록을 보존한다. 원정 재생성/상자 재출현은 원정 수명 주기 구현 때 연결한다.
- 중량 상한/과적 불이익, 창고/버리기/제작/상점, 개별 장비 인스턴스/복합 옵션은 후속이다. 목록 UI이며 최종 격자 UI는 아직 아니다.
- 실제 전투 상태는 아직 없다. 현재 귀환/아이템 차단은 미처리 습격으로 연결돼 있으며 전투 중 제한/아이템 행동/승리/도주는 S5에서 연결한다.
- 전체 콘텐츠 로딩/직렬화/복원 검증/새 탐사 기록 복사 비용은 전체 데이터 크기에 비례한다. 대형 실제 콘텐츠의 폰 성능은 별도 측정이 필요하다.
- 자동 저장 5초는 타이머가 정상 실행될 때 시도까지의 상한이다. 최초 슬롯 복원 실패 화면의 파일 복구 UI는 없다.
