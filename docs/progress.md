## 2. 이번 변경

- **자동 저장:** 기존 1초 디바운스와 함께 첫 미저장 변경부터 최대 5초에 저장을 시도한다. 연속 이동이 저장을 무한히 미루지 않는다. 저장/정지/가져오기/실패 시 예약 취소와 취소 콜백 무효화, 쓰기 직렬화/백업/실패 명시적 재시도 정책을 유지한다.
- **좌표 조회:** 깊게 고정된 콘텐츠 객체별 WeakMap에 층별 좌표 배열을 한 번 만든다. 배열 순서와 층 번호에 의존하지 않고 이후 한 칸을 상수 시간으로 찾는다. 같은 ID의 새 객체/가변 데이터에 오래된 조회표를 쓰지 않는다. 파생 인덱스는 저장하지 않는다.
- **지도 화면:** MapView를 분리하고 표시 영역과 여유 한 줄만 DOM에 둔다. 전체 크기의 스크롤 공간/실제 좌표와 접근성 인덱스를 유지한다. 플레이어 추적·수동 스크롤·리사이즈를 지원한다. 시간/자원만 바뀌면 지도 재계산을 생략하며 시야·벽 기억·미탐사 정보 숨김은 유지한다.
- **검증 경계:** runtime/validate-state.ts에 콘텐츠 대조를 모았다. 슬롯 후보마다 검증한 뒤 백업을 선택하는 순서를 유지한다. 슬롯/파일 연결부와 기존 검사 파일을 runtime으로 옮겼고 persistence의 엔진 실행 함수 import 금지 검사도 추가했다.
- **재사용 검사:** npm run test:browser와 bench:map, 합성 맵 진입점 및 verification.md를 추가했다. Playwright 1.62.1/Chromium은 별도 검사 환경에서 사용하고 제품 의존성/잠금 파일은 바꾸지 않았다. 테스트 Store 노출은 개발용 fixture에만 있으며 제품 빌드에는 포함하지 않는다.

## 4. 남은 한계

- 전체 콘텐츠를 JSON으로 읽고 검증/고정하는 비용, 전체 세이브 직렬화/복원 검증, 새 탐사 기록의 불변 복사 비용은 기록 크기에 비례한다. 실제 대형 콘텐츠에서 이 구간이 병목이면 분할 로딩/기록 구조 변경을 별도 설계한다. 임의 크기 지도의 성능을 보장한 것은 아니다.
- 저장의 5초는 타이머가 정상 실행될 때 시도까지의 상한이다. 쓰기 완료/강제 종료 무손실을 보장하지 않는다. 숨김 시 즉시 저장을 요청하지만 기기가 중단시키면 완료되지 않을 수 있다.
- 사용자가 기존 단계 마감을 수용한 것과 이번 최적화의 실제 폰 성능 확인은 구분한다. Playwright 모바일 크기 검사는 실제 폰 검증이 아니다.
- 최초 슬롯 복원 실패 화면에는 파일 복구 UI가 없다. 미래 버전/손상 슬롯 보호와 백업 1개 정책을 유지한다.
- 단일 맵 시작 칸이 임시 거점이다. 다중 맵/거점 목적지·전체 원정 수명 주기·실제 전투·야영/방치 작업은 후속 단계다.
- GPT에서 구현/검증했으며 Claude Code로 넘길 필요는 확인되지 않았다.
