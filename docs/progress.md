### S2 첫 단위 제안 — 스태미나 상태·이동 비용·기본 시간 엔진

**상태:** 제안. 코어 상태 확장·세이브 v3 변경은 아직 승인·구현되지 않았다. S1 완료 후 착수한다.

**목표:** 기존 맵 이동에 스태미나를 연결하고, 같은 순수 시간 경로에서 대기 회복을 검증한다.

**범위**

- `CharacterState`에 정수 스태미나 현재값·최대값과 이번 틱의 이동 여부를 추가한다. 현재 캐릭터는 프로토타입 배치를 유지하며 캐릭터 생성 UI·레벨은 S6다.
- 이동 목적지의 안전 여부와 이동 전 목적지 탐사 기록으로 비용을 계산한다. content의 기존 6/3/0 값을 사용하고, 탐사 감면은 `computeValue`에 수정치로 전달한다. 안전/위험 경계를 양방향으로 검사한다.
- 스태미나 부족·벽·경계 이동은 같은 상태 참조로 거부하고 비용·탐사 기록·난수를 보존한다. 성공한 이동만 비용을 차감하고 이번 틱 이동 표시를 남긴다.
- `advanceTime`·`time/tick`을 구현한다. 게임 시간은 해당 경로에서만 증가한다. 이동한 틱은 회복하지 않으며 이동 표시를 해제하고, 이후 이동 없는 틱은 현재 구역의 기존 대기/거점 회복값을 적용한다. 최대치에서 회복을 제한한다.
- GameStore에 시간 행동을 연결하고 맵 화면에 스태미나·게임 시간을 표시한다. 이 단위의 틱은 엔진/Store 테스트에서 주입한다. 실제 10초 자동 루프는 다음 단위에서 연결하며, 제품에 임시 테스트 버튼은 넣지 않는다.
- 새 상태 필드에 맞춰 SaveFile v3, 보존된 v2 스키마, 순수 v2→v3 변환을 추가한다. 제안하는 기존 v2 캐릭터 기본값은 스태미나 900/900·이동 표시 false다(D-014의 현재 임시 기준). null 캐릭터와 기존 위치·탐사·시간·난수·저장 메타데이터는 보존한다. v1→v2→v3 체인도 검증한다.
- 최신 v2 작성 코드로 만든 저장 예시와 변환·왕복·후속 행동 연속성 테스트를 포함한다.

**주요 변경 예정 경로**

`engine/core/state.ts`, `engine/systems/stamina/`, `engine/systems/time/`, `engine/systems/map/`, `persistence/`, `runtime/store.ts`, `ui/MapScreen.tsx`·문구·스타일, 관련 테스트와 docs. 기존 콘텐츠 설정값을 읽으며 새 의존성은 추가하지 않는다.

**완료 기준**

- INV-01·INV-19: 스태미나·회복·비용이 정수이며 0~최대치 유지. 비용과 같은 양·1 부족·0 비용·최대치 직전 회복 경계 검사.
- INV-02·INV-04: 모든 거부는 같은 상태 참조·자원·난수 보존, 같은 입력은 같은 상태·사건.
- 이동 전 목적지의 탐사 여부로 6/3/0 적용. 왕복·새 경로·안전/위험 경계 검사. 수정치가 실제 `computeValue`를 거치는지 검사.
- INV-03: 이동 자체가 게임 시간을 추가하지 않고, 한 `time/tick`은 한 번만 진행. 이동한 틱 회복 없음, 다음 대기 틱 회복. 다중 틱과 한 틱씩 처리 결과 동일.
- INV-05·INV-06: v1/v2→v3 변환·왕복 후 기존 필드 보존, 저장 자체 시간 진행 없음, 복원 후 이동·시간 결과 연속성.
- 전체 npm test·typecheck·build·validate:content 통과. 브라우저에서 스태미나 표시와 이동 차감 확인. 자동 회복 체감과 S2 전체 완료는 후속 런타임·휴식·습격 구현 뒤 사용자 플레이로 판정.

**다음 단위로 남기는 것**

Clock 주입·10초 틱 루프·하트비트 공백·일시정지·설정창 정지·최소 이동 간격, 위험지대 휴식·습격·팝업. 첫 단위의 대기 회복은 시간 계산 경로만 구현하며, 위험지대 대기 습격은 후속 단위 전까지 없는 부분 구현으로 명시한다. IndexedDB·오프라인 정산은 S3, 전투는 S5다.
