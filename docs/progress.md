현재 상태와 다음 작업을 기록한다. 과거 이력은 Git과 `docs/decisions.md`에서 확인한다.

**마지막 갱신:** 2026-10-14 (S2 두 번째 단위, 마지막 이동 기준의 독립 회복 D-028)

## 1. 현재 상태

- **현재 단계:** S0·S1 완료. S2 진행 중. 시간·스태미나·실시간 런타임을 연결했고, 사용자 승인으로 전역 틱과 회복 주기를 분리했다. 휴식·습격·사용자 재미 확인이 남아 **S2 전체는 완료되지 않았다**.
- **코드:** 전역 2초 틱은 gameTime만 진행한다. 마지막 성공 이동 후 2초가 지나면 독립 회복 행동으로 1 회복하고, 대기 중에는 2초마다 회복한다. 이동은 전역 틱/하트비트를 초기화하지 않는다. 정지·위험지대 공백은 시간/회복 모두 멈춘다. 200ms 이동 간격·짙은 회색 지도·검정 벽·확인한 벽 유지도 보존했다.
- **저장:** SaveFile v3·v1/v2 변환과 기존 예시는 그대로다. movedSinceLastTick은 보존하지만 회복 조건에는 쓰지 않는다. 회복 기준 시각은 세션에만 있고 새 세션/재개에는 전체 간격을 새로 센다. IndexedDB가 없어 새로고침하면 초기화된다.
- **Git:** PR #1~#11은 main에 병합됐다. 기준 main은 08eeede(트리 bb46b8a). [PR #12](https://github.com/Krsu0000/Vigil/pull/12)은 main 대상이며 `gpt-s2-runtime-20261014`에서 갱신한다. 이번 변경 전 head는 33159f8이었다. main 병합은 사용자 담당이다.
- **작업 환경:** GPT 우선(D-018). 저장소 최신 문서와 실제 코드를 기준으로 했다. Node 22.22.0·검증용 Chromium 사용. 프로젝트 의존성/잠금 파일·코어 공개 인터페이스·GameState·세이브 형식은 변경하지 않았다. 독립 회복 간격 추가로 콘텐츠 버전은 0.2.3이다.

## 2. 이번에 완료한 작업

- `time/advance.ts`: 스태미나 자동 회복을 분리하고 전역 시간과 기존 이동 표시만 진행한다. 기존 time/advanced 사건의 recovered 필드는 0으로 보존한다.
- `stamina/actions.ts`: 순수 stamina/recover { periods }·stamina/recovered. 구역별 회복량·정수·상한 검사와 computeValue를 사용한다. 게임 시간·난수·이동 표시는 유지한다.
- `runtime/loop.ts`: 단일 타이머로 전역 틱/회복/하트비트의 가까운 마감 시각 예약. 성공 이동만 회복 기준을 초기화. 효과는 시각 순서로, 동시에는 전역 틱→회복 순서로 처리한다.
- `runtime/store.ts`: 세 시스템 행동/사건을 같은 dispatch·상태·구독 경로로 조합한다.
- `content/`: stamina.recoveryIntervalMs=2000 추가, contentVersion=0.2.3. 전역 tickMs=2000은 유지한다. 기존 *RegenPerTick 이름은 회복 주기당 양으로 유지한다.
- `ui/`: 이전 이동 틱 제외 안내를 마지막 이동 기준 안내로 바꿨다. 전역 틱 간격·회복 간격·회복량을 표시한다.
- 사용자 승인에 따라 game-design의 대기 정의를 수정했다. architecture·features·roadmap·D-028과 이 문서도 실제 결과에 맞췄다.

## 4. 사용자 확인과 제한

- 최초 실제 폰 정상 이동은 사용자 확인을 받았다. 벽 개선 후 S2 진입도 사용자 지시로 수용했다. 이번 회복 변경/백그라운드 복귀/폰 체감 확인을 새로 받은 것으로 기록하지 않는다.
- 사용자는 기존 1→2틱에서 회복을 보지 못했다고 보고했고, 틱 2초 단축 뒤 전역 틱과 독립 회복 분리를 승인했다. 당시 기기 상태/수치는 알 수 없어 원인 확정과 승인된 규칙 변경을 구분한다.
- 실제 독/출혈·휴식/습격·일반 게임 창은 아직 없다. 이번 검사는 전역 틱 주기가 이동으로 밀리지 않는 계약이며 해당 기능 구현 완료가 아니다.
- 안전 구역의 열린 세션 지연은 마감 시각 순서로 처리한다. 창 닫기 뒤 정산·24시간 상한·브라우저 저장/백업은 S3다.
- S3 불러오기 연결은 루프 종료→원자적 Store 복원→새 루프 시작으로 하고 정산과 실시간 중복 적용을 검사해야 한다. 현재 저장 자체는 시간/회복을 진행하지 않는다.
- 미해결 코드 오류 없음. S2 전체 재미/위험 완료 기준은 아직 충족하지 않았다.
