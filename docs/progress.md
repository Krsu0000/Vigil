## 2. 이번 변경

- persistence/browser-repository: 네이티브 IndexedDB DB 구조 버전 1. 슬롯/세대 읽기와 primary/검증된 backup/세대의 원자적 쓰기. 용량 오류·다른 탭 세대 충돌 시 전체 취소.
- persistence/load-slots: primary 우선 형식/변환/구조/콘텐츠/활동 검증, 오류 시 backup. 두 슬롯 모두 없을 때만 새 게임. 둘 다 오류 또는 미래 형식이면 기존 데이터 보존/시작 실패.
- runtime/startup·auto-save: 저장 복원/빈 저장소 초기화·Store 구독·1초 디바운스·숨김 이벤트·직렬 쓰기·성공 후 revision 갱신·실패 UI/명시 재시도. React 효과 정리는 즉시 저장 조건이 아니다.
- main은 저장 복원을 기다린 뒤 루프를 시작한다. 저장소 불가 시 명시적 메모리 모드, 새로고침 초기화 안내. 저장 실패 자체는 메모리 플레이를 막지 않는다.
- UI: 자동 저장 준비/중/완료/실패·백업 복원·재시도, 오프라인 회복 미지원 안내. 다른 탭 저장을 덮어쓰지 않으며 충돌 뒤 최신 상태를 불러오려면 새로고침이 필요하다.
- CLAUDE.md에 동일 코드의 기준선 재사용·개발 중 관련 검사·통과 출력 요약을 기록했다. D-030·architecture·features·roadmap도 현재 코드/검증에 맞췄다.

## 4. 사용자 확인·제한

- 최초 Pages 실제 폰 정상 이동은 사용자 확인 완료. 벽 개선 뒤 S2 진행 지시로 S1 마감 수용. 이번 휴식/습격/저장의 실제 폰·재미·위험 판정을 새로 받은 것으로 기록하지 않는다.
- 이전 1→2틱 회복 미관측 보고 뒤 2초 틱/독립 회복(D-028)을 승인받았다. 당시 폰 수치/시점이 없어 원인 확정과 규칙 변경을 구분한다.
- 모바일 크기/터치는 자동 브라우저 검사다. 합성 visibilitychange는 저장 경로 확인이며 실제 폰 강제 종료 전에 쓰기가 완료되는지는 미검증이다. 기본 최근 1초 변경은 비정상 종료로 유실될 수 있다.
- Pages main과 각각의 미리보기는 출처가 달라 저장소를 공유하지 않는다. 브라우저/기기 사이 이동용 내보내기/가져오기는 다음 단위다.
- 오프라인 연결 시 savedAt/settledUntil·실시간 진행·중복 정산·시각 역행/상한을 따로 검사해야 한다. 이 저장 단위의 복원 자체는 게임 시간을 진행하지 않는다.
- 즉시 귀환 제약은 미정이다. 이번 단위는 해당 규칙을 확정하거나 귀환을 구현하지 않았다. 일반 인벤토리/코덱스 창도 미구현이다.
- 미해결 코드 오류 없음. S2 사용자 판정·S3 전체 완료 기준은 미충족이다.
