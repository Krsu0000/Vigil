## 2. 이번 변경과 완료 범위

- `engine/systems/time/settle.ts`: from/to를 주입한다. 실제 시작점은 max(from, settledUntil, lastActiveAt)이며 복원 from은 savedAt이다. 같은 시각/역행은 무변화, 양의 구간은 24시간 상한 적용 후 to까지 소비한다. 전역 틱과 회복 간격은 각각 나눠 기존 advanceTime/stamina/recover를 조합한다. 위험지대·미배치·미처리 습격은 보상 없이 기준만 갱신한다. 게임 시간 정수 상한 초과는 부분 지급 없이 거부한다.
- `runtime/startup/store`: 후보 검증→Store 복원→정산 1회. 새 시드/ID를 생성하지 않는다. `main`은 정산 결과 저장을 시도한 뒤 같은 루프를 UI에 전달한다. 저장 실패 시 기존 슬롯 보존/안내/메모리 플레이/재시도를 유지한다.
- `runtime/loop`: 일반 실시간은 기존 단조 시계/마감 순서를 유지한다. 유예 초과 안전 구역 공백은 마지막 실행 완료 시각 이후만 time/settle로 처리하고 기준을 다시 잡는다. 위험지대의 공백 정지·수동 정지/설정창 규칙은 유지한다. 보이기 이벤트의 별도 정산과 실시간 따라잡기를 중복 실행하지 않는다.
- `runtime/auto-save`: 구독 전의 초기 정산도 저장 대상으로 잡고, beforeSnapshot에서 같은 루프의 미처리 실행분을 반영한 뒤 상태와 savedAt을 함께 캡처한다. 상태 변경이 없는 정지 중에도 숨김은 저장 시각 체크포인트를 남긴다. 쓰기 직렬화·실패 보존·명시 재시도를 유지한다.
- UI의 오프라인 미지원 안내를 거점 최대 24시간 회복/위험 구역 제외 안내로 갱신했다. 새 화면/귀환 버튼은 추가하지 않았다.
- **이번 거점 정산의 코드·자동/브라우저 검증 단위 완료.** 실제 사용자 폰 확인 및 S2/S3 전체 마감과는 별개다.

## 4. 사용자 확인·제한

- 최초 Pages 실제 폰 정상 이동은 사용자 확인 완료. 최근 휴식·습격·저장·거점 오프라인의 실제 폰 확인과 S2 재미/위험 체감 평가는 새로 확인한 것으로 기록하지 않는다.
- 자동 브라우저의 모바일 크기/터치는 실제 폰 검증이 아니다. 폰 강제 종료/백그라운드에서 쓰기 완료 여부는 미검증이며 최근 1초 변경은 비정상 종료로 유실될 수 있다.
- Pages main과 미리보기는 출처가 달라 저장을 공유하지 않는다. 다른 브라우저/기기 사이 파일 이동은 미구현이다.
- 저장/복원 함수 자체는 상태·게임 시간을 바꾸지 않는다. 정산은 별도 dispatch다. 저장 실패 후 재시도는 현재 상태만 기록하며 정산하지 않는다.
- 부분 틱/회복 시간·수동 정지·팝업 열림은 세션 값이므로 저장하지 않는다. 새 세션/긴 공백 뒤에는 간격을 새로 센다. 유한 보호·만료/지속 효과를 추가하면 일괄 처리 대신 해당 시각에 정산을 분할해야 한다.
- 새 코어 구조·SaveFile 호환성·핵심 규칙 변경 없음. 미해결 코드 오류 없음. GPT에서 구현/검증했으며 Claude Code로 넘길 필요는 확인되지 않았다.
